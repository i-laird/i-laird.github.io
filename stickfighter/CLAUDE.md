# Stick Fighter 2000 — game documentation

This file is the full documentation for the Stick Fighter 2000 game. It is auto-loaded when files in `stickfighter/` are read or edited; the root `CLAUDE.md` keeps only the chunk contract (loader handshake, `api` bridge, assembly workflow) and a short cross-cutting-invariants list.

## Source layout & assembly

This directory is the game's **source of truth**. The served `stickfighter.js` at the repo root is a **generated artifact**: the 23 `NN-*.js` part files here are concatenated in filename order inside the single `function openStickFighter(xp, api) { … }` closure by `scripts/assemble-sf.js`.

- **Workflow: edit a part → `npm run assemble` → commit both** the part and the regenerated `stickfighter.js` (`npm run serve` and `npm run build` assemble automatically). Never edit `stickfighter.js` directly — `test/stickfighter-assembly.test.js` pins the artifact byte-for-byte to the parts and fails CI on drift or direct edits.
- Each part is a **fragment of that one function body** — all parts share a single lexical scope exactly like the old monolithic file, so functions and state cross part boundaries freely (no imports, no bridges between parts). Parts are individually lintable; the eslint browser block sets `globalReturn` because `01-head.js` opens with the re-entry guard's top-level `return`.
- Parts use normal 2-space indentation. New part files must match the `NN-*.js` pattern or the assembler silently skips them (the assembly test's inventory check catches this).
- The part map: `01-head` (api destructure, canvas/hud/audio, tuning consts, SF_SPEED, sim clock + seeded `rnd()`) · `02-state` (all run state + netplay vars + class tuning/SPELLS) · `03-trophies` · `04-boons` (boons + banes) · `05-init` (`init()`/`setupCoop()`, daily seed, hero/target helpers) · `06-upgrades` (tree, shop, meter/mana gauges) · `07-sfx` · `08-render-horde` · `09-render-bosses` · `10-render-field` · `11-render-intro` · `12-combat` (killEnemy/strike/endRun) · `13-leaderboard` · `14-netplay` · `15-screens` (connect + death screens) · `16-spawn` · `17-bosses` (Vader/Sidious/DIO/Ian logic) · `18-enemy-ai` (`updateEnemy`) · `19-boss-intro` · `20-loop` (fixed-timestep driver + the ~1,500-line `loop()`) · `21-hero-actions` (movement, dash, swing/shoot/cast/scythe, summons) · `22-flow` (interlude transitions, stopGame, warp cheats) · `23-input` (`onKey`, wiring, boot).

## Cross-cutting invariants (bite people outside this directory too)

- **Sim-balance version lives in FOUR places** and must bump together on ANY gameplay-affecting change (damage, speeds, AI, economy): `recHdr.v` (in `05-init`), `startWatch`'s check (`13-leaderboard`), `NET_SIM_V` (`02-state`), and the hal-worker's `REPLAY_VERSION`. Miss one and stored replays silently re-simulate under new rules, or netplay peers on stale sw.js chunks desync. This is also why **the site and `~/hal-worker` deploy together**.
- **A pure refactor needs NO version bump** — the 2026-07 split into parts was verified token-stream-identical, so replays recorded before it still play back bit-exactly.
- **`noPersist()` (= `replayMode || netplay`) gates ALL persistence** — achievements, trophies, upgrades/tokens/maxwave, wolf-kills, local best, ending/endless/hard flags, and the leaderboard. Any new persisted state must respect it.
- **The site tracks only two SF easter eggs** (`stick-fighter` on boot, `sf-platinum` on a full trophy case). In-game trophies go in `SF_ACH` + `sfUnlock('<id>')` and must NOT touch the site's `ACHIEVEMENTS` or the OG-image egg count.
- **Score/elite math is paired with the worker**: a dread troll's 960 ×-multiplied points equals `verifyRun`'s per-kill ceiling constant (`kills * 960`) — raise both together.
- **Determinism rules for new code**: all gameplay randomness through `rnd()` (never `Math.random()`), timing off the `tick` counter (never wall clock), never put `rnd()` behind a settings check (draw first, gate only the visual), and sim mutations only via the tick-stamped input stream (`pend`/opcodes) — never directly from a DOM event.

## The game

**Stick Fighter 2000** (the lazy `stickfighter.js` chunk — chunk contract in the root CLAUDE.md’s Architecture section; source layout above) — fantasy horde-survival game hidden as a desktop icon inside the `gui` XP desktop (desktop only, not in `games`). Doesn't use the shell (it lives on a transparent canvas over the desktop with its own key listeners). Velocity-based movement + SPACE/Shift dash (i-frames, afterimage ghosts, 72-frame cooldown shown in the HUD). **Local couch co-op (`coop` flag) + hero classes:** the intro screen is a character-creation screen (`menuTop`/`subSingle`/`subMulti`/`classSel`/`classSel2`/`introRow`, rendered by `drawIntroScreen` — a full title scene: night sky + backlit horde-silhouette march along the ridge, gold wordmark, pill-style mode/class selectors, footer hint bar; deliberately `rnd()`-free so title frames never advance the seeded sim stream): the menu is **two-level** (`menuTop` SINGLEPLAYER/MULTIPLAYER; `subSingle` NORMAL / ☠ HARD / ☀ DAILY; `subMulti` LOCAL / 🌐 HOST / 🌐 JOIN — HARD is a selectable pill only once `hardUnlocked`, skipped while locked) (**←/→ cycle the value, ↑/↓ switch rows, 1/2/3 quick-jump to solo / couch co-op / daily, Z/Enter/Space begins** — starting calls `init()` fresh so the chosen seed applies; **LOCAL couch co-op first shows a confirm party sheet** (`introConfirm`/`drawIntroConfirm` — both mannequins + controls; a second Z/Enter starts, Q/Backspace backs out, other intro keys are swallowed while it's up) so a stray Enter can't launch mid-decision; HOST/JOIN hand off to the netplay connect screens instead, which end in a both-players READY lobby — see ONLINE CO-OP below), one class row per hero picks **melee / ranged / caster / necro / dragoon** (`CLASSES`; persisted in localStorage `ilaird_sf_cls`/`ilaird_sf_cls2`, re-applied on R-restarts via `init()`/`setupCoop()` reading `classSel`/`classSel2` into `h.cls`), and a **live mannequin preview** (`drawClassPreview` — the hero at 1.3× with the chosen class's real weapon draw, swaying facing, over a class-colored spotlight; two mannequins in 2P) shows the character being built. Defaults (1P · melee) keep the classic run one Enter away — the headless determinism test starts by dispatching Enter, takes the first boon with Z (the run-start boon menu opens synchronously at begin, so the pick lands at wall-time zero on any cadence), then holds ArrowRight to move. **Melee is the classic kit, unchanged** (sword in the stone / lightsaber, `trySwing`). **Ranged** (`tryShoot`) is the **skill-shot class — no auto-aim**: the attack key looses an arrow in the direction being held (8-way, i.e. along `h.fx/fy`, the facing set by movement keys; the bow draw points the same way), pushed into `arrows` with `kind:'parrow'` (drawn green-fletched; a per-arrow `hitSet` stops a piercing arrow re-hitting the same foe; harmless to heroes, and both the blade's deflect loop and Luke's arrow-batting skip `parrow`). **Caster** (`tryCast`) is the **spellbook-and-mana class**: the attack key casts the **selected page** of the `SPELLS` table (bolt / nova / fire / storm — each with its own `cost`, `cast` ticks, and orb color), and a **cycle key turns the page** (solo: C or E; co-op: `.` for P1, E for P2 — queued through `pend.cycleP1/P2` and **recorded as opcode 11** with the hero index, because the selection changes what the attack key does). Every cast **drinks mana up front** from the per-hero pool (`h.mana`, cap `up.manaMax` base `MANA_MAX` 100, refilling `MANA_REGEN` 0.15/tick — deliberately well short of bolt-spam, and **the well holds its breath for `MANA_HOLD` 40 ticks after every cast** (`h.manaHoldTick`, set at spend time in `tryCast`, gated at the regen line in the loop; the gauge label reads "settling…"), so while chain-casting there is effectively NO trickle at all — the pool and the kill sparks are everything, and regen only flows in the spaces between casts. Mana is meant to feel precious; kill sparks pay **+5** (Siphon 10) so aggression, not waiting, is the sustain × `up.manaRegen` in the loop's caster block) — a press with no mana or no mark in reach fizzles free, a cast whose mark dies mid-incantation refunds half, and **every kill sparks +5 mana back** (soul sparks, in `resolveCast`), so bold play sustains itself. Casting is still a deliberate **incantation** (`h.castT`/`h.castMax`, staff orb swells in the spell's color via `drawHeldStaff`, resolved through `resolveCast()` → `castBolt`/`castNova`/`castFire`/`castStorm`): **ARCANE BOLT** (always known, 18 mana) arcs to the nearest foe within `ZAP_R` (170; +40 grace at release) and chains `up.zapJumps` hops of `ZAP_HOP`; **FROST NOVA** (tree unlock, 34) is the old auto-nova made manual — an always-erupting `NOVA_R` ice ring, brief freeze, boss/wraith-immune like the powerup; **FIREBALL** (tree unlock, 46) hurls at the nearest mark within `FIRE_TGT_R` and erupts `FIREB_R` *there* (kill + shove); **TEMPEST** (Archmage's page, 70) leaps six marks at `STORM_R`/`STORM_HOP` striking for 2. There is **no auto-cast anymore** (the old `novaCd`/`fireCd` fields are gone). A per-caster **mana gauge** (`drawManaGauge`, bottom-right mirroring the summon gauge, outside the shake transform) shows the pool, a notch at the selected page's cost, and the cycle key (the same function draws the necromancer's souls bar — raise-cost notch + minion-slot pips). **Necro** (`tryScythe`) is the **army-of-the-dead class — one key, two verbs**: the attack key REAPS a wide soul-scythe arc (`SCYTHE_R` 82, ~192° in front, `rangedHit` rules, cooldown `up.scytheMs`), and any **husk** caught in the sweep **RISES** as a minion while **souls** and the cap allow (`RAISE_R`, cost `up.raiseCost` from the per-hero `h.souls` pool, `SOULS_MAX` 100 — **no passive regen**: souls come only from kills, `SOUL_KILL` 6 per scythe kill / `SOUL_MKILL` 3 per minion kill, so the class runs on aggression). Grunts (goblin/wolf/archer/troll) felled while a necromancer stands leave **husks** (pushed in `killEnemy`, capped `HUSK_CAP` 12, decaying over `HUSK_T` × `up.huskMul`, elite husks remembered). **Minions** (`minions[]`, updated in their own loop block after the caster clock) hunt the nearest horde piece (support pieces included, bosses excluded), claw through `rangedHit` (`up.minionDmg`), take contact damage back from grunts, live `MINION_T` (~21s, a draining life-ring at their feet), and are drawn as their living sprite in spectral teal (`drawMinion` reuses `drawGoblin`/`drawWolf`/etc.; husks via `drawHusk`). **Body-block is the point**: `hordeTarget` returns a minion within 130px before any hero, so raised dead bait the pack. **Boss rooms banish the lot** (the per-tick block clears `minions`/`husks` whenever `champsBanned()` — "your dead abandon you" — and `killEnemy` drops no husks there), mirroring the champion ban. The **GRAVE tree** drives `up.minionCap/raiseCost/huskMul/scytheMs/minionHp/minionDmg/minionBoom/trueForms/reaper`: Restless Dead (3rd minion), Grave Pact (cheap raises), Preservation (longer husks), Reaper (faster sweeps, +3 souls/kill), Deathburst (falling minions erupt — `knockback` + frost-ring visual), True Forms (wolf minions lope at 2.3, archer minions loose `parrow` spectral arrows — hero-safe by the existing arrow rules), and the capstone Lord of the Fallen (2 tokens — 4th minion, hp 3, dmg 2). **Dragoon** (`tryFlap` + `joustSweep`) is the **arcade-JOUST class — your speed IS the weapon, and contact is never neutral**: every foe carries a per-type **skewer bar** (`JOUST_BAR` px/tick — goblin/archer/support 3.2, wolf 4.2, wraith/guard/named bosses 4.6, troll 5.2, ogre 5.6; elites +0.5, dread +0.9), and `joustSweep` (called per mounted hero right after movement, BEFORE the contact loop) lands a lance hit on any foe inside `e.kr + PLAYER_R + LANCE_R + up.lanceR`, roughly ahead of the velocity (dot ≥ 0.35), while the rider flies at or above its bar — damage through `rangedHit` (so no-flinch bosses stagger and never die to a pass; grunts are skewered clean, one hit per pass via the tick-stamped `e.joustTick`). A **survivor caroms the rider off** (velocity reflected off the contact normal at 0.9×) so momentum never carries you into a body you only wounded; below the bar (or struck from the flank/behind) **nothing intercepts — the ordinary touch-death contact loop right after the sweep is the “or you die” half of the rule**. Movement is Joust physics (a `dragoon` branch in `moveHero`: friction 0.93, accel 0.3, cap `DRAG_CAP` 6.4 × `up.dragCap` vs everyone else's 4.3), and the attack key is a **WING FLAP** (`tryFlap` — an impulse `FLAP_IMP` 3.0 along the facing on a `up.flapCd` tick cooldown; no weapon at all), so the class kills ONLY by jousting. The bottom-right gauge (`drawManaGauge`'s `drag` branch) shows momentum against the cap with a notch per Joust tier (goblin · wolf · troll). The **SKYLANCE tree** drives `up.dragCap/lanceR/flapCd/joustDmg/tailwind` (Windrider/Gale Wings speed, Long Lance reach, Swift Flap, Trample +1 damage, Tailwind kill-surge; capstone **Sky Lord**, 2 tokens); boons: GALE (+8% cap), SHRILL CRY (`bn.cry` — a skewer kill `knockback`-scatters the pack), BROAD PENNON (+10 reach). Draws: `drawHeldLance` (couched along the VELOCITY, tip ignites `DRAGOON_COL` at goblin-bar speed — steady, reduced-motion safe), winged-helm + rider's-wings garb in `heroFigure`. The sweep consumes **no `rnd()`** and adds no opcodes (flap = the ordinary attack edge), so replays/netplay carry it unchanged; `stickfighter-dragoon.test.js` pins the rule headlessly (gallop → kills while alive; standing still → death). The joust deliberately skips `ian` (the choice is not made with a lance) and respects `untouchable()`/`dioStopT`/`ianActive`. **BOONS (per-run 1-of-3 picks):** on top of the permanent tree, each NORMAL run offers a boon menu THREE times — at run start, when the Witch-king falls, and as mercy's reward in `finishIanSpare` (the KILL ending gets none). **HARD MODE inverts this entirely: no boons at any of the three moments — instead the run OPENS on a `BANES` menu ("CHOOSE YOUR BANE", red-styled via `boonMenu.bane`, `openBaneMenu`) and one burden must be taken** (6 shared banes: Lead Boots −12% speed, Dulled Arms +25% attack cooldowns, Heavy Toll +1 token on every `upCost`, Marked +8% open-field horde speed at `makeEnemy` — scripted bosses keep their tuned pace, Blood Price +50% summon cost, Miser's Curse zero coin meter). Bane ids share the pick namespace, so opcode 12 and the worker regex cover them unchanged, and hard replays open on the bane menu because `hardMode` rides the replay header. `BOONS` (stickfighter.js) holds 6 shared + 3 per class (filtered to classes present, like the trees); effects are **ephemeral by design** — `bn` (per-run effect object) and any `up` tweaks rebuild each `init`, so nothing persists. `rollBoonOffer()` draws 3 with `rnd()` (a pure function of seed + roll position — no recording needed for offers); the **pick** is sim input, recorded as **opcode 12** (boon id, worker-validated by the same snake_case regex as shop buys) in the tick+1 slot. ⚠ **The run-start menu opens SYNCHRONOUSLY in the begin / R-restart / `startReplay` handlers right after `init()`** — the offer roll is then the seed's first draws in live play and replay alike, and a headless driver can pick with `z` before pumping a single frame (cadence-independent, which is what keeps the 60/120 Hz determinism test valid). The mid-run menus open sim-side (inside `killEnemy` / `finishIanSpare` ticks). `boonMenu` pauses the sim (drawn by `drawBoonPanel`, navigated ←→ + Z, swallowing other keys); daily runs get boons too — same seed → same offers for everyone, the pick is the player's skill like class choice. Hooks live at: `moveHero` (Fleet Foot), `strike` (Deathward — deliberately BELOW the Aegis, which refreshes per wave), the coin pickup (Golden Touch), `grantBossToken` (King's Tithe), `killEnemy` pts (Bounty), `resolveCast` (Siphon), `tryCast` (Flicker), `tryScythe`/minion refund (Grave Harvest), and the raise (Restless); the rest tweak per-run `up` fields directly at pick time. **The TROPHY CASE (Stick Fighter's own achievement system):** the game keeps its own 28-trophy ledger (`SF_ACH` in stickfighter.js — ids like `first_blood`/`witch_king`/`ian_spare`, plus a hard set: `unscathed` (five waves, no blow — `runFlawless`, cleared in `strike()` past the dodge guards), `swift` (wave 5 under 3 min, tick-gated), `deep_15`, `dark_hour` (hard-mode Witch-king), `daily_crown` (rank 0 back from a daily `lbSubmit`), `wolf_100` (100 lifetime elite-wolf kills — `wolfKills` counter in `ilaird_sf_wolfkills`, replay-gated at the increment), `the_weight` (the Ian choice held ≥60s — `ianChoice.t` at choose time), `hoisted` (a keg's friendly fire kills a shaman); boss/ending/hard ones are `secret`, masked as `???` until earned), persisted account-wide in `ilaird_sf_trophies` (deliberately NOT per class-profile). `sfUnlock(id)` is idempotent, **no-ops during a watched replay**, queues a gold toast (`drawTrophyToasts`, called from every render path — intro, death, shop, live), and persists. The intro screen shows a `🏆 trophy case N/20 · press T` hint; **T toggles `drawTrophyCase`**, a two-column overlay (T also closes; Escape is avoided — it's the desktop's shutdown key; while open, other intro keys are swallowed). **The SITE tracks only two SF eggs**: `stick-fighter` (fired raw via `_unlockAch` at the top of `openStickFighter` — `replayMode` isn't initialized yet there, and a boot is never a replay) and `sf-platinum` (fired by `sfUnlock` when the case is FULL). The five old SF site eggs (`excalibur`/`ogre-slayer`/`witch-king`/`dark-lord`/`world-stopper`) were removed from `ACHIEVEMENTS` and live on as trophies — a one-time **migration** in the `sfTrophies` loader seeds the case from any of those still in `ilaird_eggs`. ⚠ When adding an SF trophy, add it to `SF_ACH` and call `sfUnlock('<id>')` at the moment — do NOT touch the site's `ACHIEVEMENTS`/OG count for in-game trophies (that's the whole point); the platinum threshold is `SF_ACH.length`, so it self-adjusts. Adding a class widens the intro class row (the pill width is computed from `CLASSES.length`, so it auto-fits) and the class-index bounds everywhere (`classSel` clamps, `startReplay`, and the worker's `validateReplay` `c1`/`c2` ≤ 4 as of the 5th class, the dragoon — another reason the site + hal-worker must deploy together). Both new kits damage through `rangedHit()` (same no-flinch rules as `trySwing`: vader/sidious/dio/ogre take a stagger, grunts take a gentler shove) and share `untouchable()` (the scripted-intro skip rules). All attack call sites go through `tryAttack(h)`, which dispatches on `h.cls`. `drawHero` draws `drawHeldBow`/`drawHeldStaff` for the new classes, and hero bodies are class-dressed via `heroFigure` (melee: gold headband + sash; ranged: hood + feather + back quiver; caster: wizard hat + flowing robe replacing the legs — garb mirrors to `h.fx` facing, `mono` mode keeps silhouette-only garb for dash ghosts and the downed gray; `heroTint(h)` supplies the body color everywhere including the weapon arms/fists, so P2's arm is green and dash-cyan reaches the held weapon). **Blades are melee-only**: the stone only spawns/arms for melee heroes, `saberPickup` is only laid down (and only grabbable) when a melee hero is in the party, and `armSaberAll()` arms melee heroes only — ranged/caster keep their own weapons through the interludes. Class trees in the shop are filtered to classes present in the party (see Upgrades below). **Everything is gated behind `coop` (default false), so single-player is byte-identical — the deterministic sim and its tests are untouched.** **ONLINE CO-OP (netplay):** MULTIPLAYER → HOST/JOIN runs the same 2-hero co-op sim across two browsers as **delay-based lockstep P2P** — host = P1, client = P2, both peers get the full solo bindings. Gameplay is a WebRTC DataChannel (reliable+ordered, STUN only — no TURN, so symmetric-NAT pairs fail to a retry screen); the only server involvement is signaling through hal-worker: `netStartHost` POSTs one non-trickle SDP offer to `/mp-host` → 5-char room code (shown on a canvas connect screen, `drawNetScreen`), the joiner types it (`/mp-offer` + `/mp-join`; **on the code-entry screen Backspace-on-empty backs out — Q is a valid code character there**, everywhere else Q backs out/leaves), the host polls `/mp-answer` every 2s. On channel open the client's `hello` {NET_VER, NET_SIM_V, class, dims} opens a **READY LOBBY** (version-checked both ways via the host's `lobby` reply): both players see both hero picks side by side on podium previews, ◀ ▶ re-picks live (`cls` messages; re-picking auto-un-readies you), and Z/Enter toggles ready (`rdy`) — **the run starts only when BOTH are ready** (`netLobbyMaybeStart`, host-side: it then builds `cfg` = the authoritative run header {fresh seed, both classes, hd:0, the HOST's up0/tk0/mw0 snapshot, gw/gh = min of both screens} → `ready` → `go`) and both sides run `netBeginRun()`. (`dc.onopen` must not clobber a `lobby` phase already set by a same-tick `hello` — guarded.) — a `startReplay`-style impersonation (`netSaved` restores the local selections on exit; `setGameDims` letterboxes the negotiated field; the `init()` netplay branch reads the cfg like a replay header and disarms the recorder). **Lockstep:** every tick each sim samples its LOCAL held-keys nibble + staged edges (`netLocal`, queued in onKey) into a frame for `tick + NET_DELAY` (5), buffers + sends it (`{t:'f', r: netRunId, k, m, e, s, h}`), and `frameStep`'s gate refuses to run a tick until BOTH frames for it are buffered (`netCanStep` — covers paused/menu/death ticks too, since `tick` advances there and pause duration is part of determinism; a blocked frame draws the `drawNetWait` badge, render-only). The combined mask feeds the input sampler exactly like `repMask` (`im = netMask`). **The iron rule: the sim is never mutated outside the tick-stamped input stream** — host menu confirms (boon 12 / buy 7 / continue 8 / boss-intro 9 / Ian 10) go through `netQueueEvent` (stamped `tick + NET_DELAY + 1`, safe because the ordered channel bounds how far ahead the peer can be) and are applied by a feeder identical to the replay feeder; the client's menus are read-only ("Player 1 is choosing…"); the client's summon crosses as `pend.summon2` (consumed after the host's, so the shared meter spends deterministically; solo/replay never set it — no `recHdr.v` bump); **the warp/grant cheats are disabled online** (they'd desync instantly). A djb2 checksum of load-bearing state crosses every 60 ticks (`netChecksum`) and any mismatch ends the run cleanly ("DESYNC"); stale messages from a previous rematch are dropped by `netRunId`. **Nothing persists** out of an online run — `noPersist()` (= `replayMode || netplay`) gates achievements, trophies, upgrades/tokens/maxwave, wolf-kills, local best, the Ian-ending/endless/hard flags, and `endRun` skips the leaderboard entirely; `beginRunProof` never fires. R on the death screen is a host-only rematch (`{t:'restart', seed}` → both `netBeginRun` on the same cfg + new seed); Q anywhere leaves (`netLeave` restores `netSaved`, tears down, sticky `netNotice` on the intro); the desktop's Escape shutdown calls `netTeardown()` via `stopGame`. **A mid-run transport drop does NOT end the run — it auto-reconnects, for as long as it takes** (`netStartRecon` in `14-netplay`): the lockstep gate already freezes both sims when frames stop, so the drop handlers (channel `onclose`, pc `failed`, or pc `disconnected` persisting a 10s grace — a merely lagging/tabbed-away peer with a live link is deliberately NOT a drop) tear down only the transport, keep all run state, and re-signal through a **rejoin room** both peers derive from (room code, seed) via `rejoinHash` — `'R'+5` chars, a keyspace minted codes can't collide with. The host re-posts a fresh offer to `/mp-host {rejoin}` each ~26s attempt (the worker **overwrites** the rejoin room and stamps a `gen`; the joiner polls `/mp-offer` every 2.5s and must echo `gen` on `/mp-join`, so a stale answer 409s instead of pairing with the wrong offer). Attempts repeat for up to **10 minutes** (`NET_RECON_MAX_MS`; the deadline is enforced by the attempt loop's `live()` guard, checked every ~2s, and concedes via `netLeave` with a sticky intro notice) — Q (or desktop shutdown) ends the wait sooner; `drawNetRecon` (in `15-screens`, drawn from `frameStep`'s badge branch) shows the attempt count + a give-up countdown. On channel reopen both peers send `resume {tick, have}` and refill what the drop swallowed: each re-sends its own retained input frames past the peer's `have` (the loop keeps a trailing 30-tick window of OWN frames for this — remote frames are still deleted at consumption), and the host re-sends `netEventLog` entries (every menu event ever queued) past the peer's tick after the client wipes its pending list at reopen — no event can be lost OR double-applied. Then the gate simply unblocks and lockstep continues bit-exact; the checksum tripwire keeps watching, and a real DESYNC still ends the run via `netLeave`. R-rematch is blocked while `netRecon` is set (a restart the peer can't hear would desync). `NET_VER` is 2 (the resume protocol is a wire-protocol change; `NET_SIM_V` unchanged — no gameplay change). `NET_SIM_V` **must track `recHdr.v`** — the handshake refuses mismatched builds (sw.js can serve one peer a stale chunk after a deploy) with "reload the page". In 2P a second hero `p2` (green, `P2_COL`) joins: **P1 = arrows move · Right-Shift dash · `/` swing; P2 = WASD move · Left-Shift dash · `F` swing** (the two Shifts are told apart by `e.code`). Helpers `heroesAll()`/`heroesLive()`/`nearestLiveHero()`/`nearHero()` thread both heroes through the sim; `hordeTarget(e)` splits open-field grunt aggro to the **nearest standing hero**, while the scripted boss/set-piece foes (wraith/witchking/vader/sidious/dio/guard/trooper/ian) lock onto `bossTarget()` — **P1 while standing (cinematic 1-on-1), but the survivor if P1 is down** (otherwise the boss would keep hammering P1's downed body while the other hero runs free). Boss **movement** flows from `tgt` (so the wraith ring + witch-king hover read `tgt`, not `player`), and the boss **attack helpers that compute aim/reposition in separate functions** — `sidiousFlank` (the Emperor's leap), `forcePush`/`vaderThrow` (Vader), `startBarrage`/`startRoller` (DIO) — read `bossTarget()` too. The one exception is Vader's **Force choke**, which stays P1-only (its struggle/escape + lift animation are keyed to `player`); it's simply not chosen while P1 is down. The whole flow is **best-effort and degrades silently** — worker unreachable or score 0 → `lbState='off'`, the original local-best screen. **Run proof (minimal, O(1) — proof of TIME + PLAUSIBILITY, not proof of play):** when a run starts, `beginRunProof()` fire-and-forgets `POST /run-start`, which mints an HMAC-signed **run token** (`{typ:'run', rid, iat}`, same secret as the LLM-HAL session tokens) pinning the run's true start time; `endRun()` freezes `lbTicks`/`lbKills`, and `lbSubmit()` sends `{token, ticks, kills}` with the score. The worker's `verifyRun()` rejects (400) any submit whose token is missing/forged/expired/**already used** (single-use via a TTL'd DynamoDB counter on `rid`), whose tick count outruns wall-clock time since `iat` (you cannot claim a 20-minute run 20 seconds after starting; 66 ticks/s + slack), or whose stats break the game's own rules — minimum run length, wave pacing (≥~250 ticks/wave), kill budget vs. wave (spawn-pipeline bound), score budget vs. kills+ticks (≤720/kill + <20000 flat boss bonuses + ≤1/tick passive; constants deliberately generous — they reject the absurd, not the marginal). `REQUIRE_RUN_PROOF=0` is the worker-side kill switch; a rejected/tokenless submit degrades to `lbState='view'`. Anything the client computes is forgeable, so **full proof of play remains the documented upgrade path**: re-simulate the recorded per-tick inputs server-side over the deterministic sim — the recording now EXISTS (see replays below), only the server-side re-run doesn't. **Replays / "watch a legend":** every live run is recorded — `recPush` appends `[tick, code, arg?]` events (codes: 0 held-direction mask change · 1–4 P1/P2 dash/attack at pend consumption · 5 summon · 6 choke-mash · 7 shop buy (by upgrade id) · 8 shop continue · 9 boss-intro advance · 10 the Ian choice · 11 spell-page cycle (arg = hero index) · 12 boon pick (arg = boon id)), and `recHdr` (built in `init()`) captures every piece of persistent state the sim reads at start: `{v, seed, c1, c2, coop, hd (hard mode), up0 (owned upgrade ids), tk0 (token balance), mw0 (lifetime maxwave)}`. **`v` is the SIM-BALANCE version (currently 4 — the mana-regen nerf): bump it in all FOUR places — `recHdr`, `startWatch`'s check, `NET_SIM_V` (netplay's handshake check), and the worker's `REPLAY_VERSION` — on ANY gameplay-affecting change** (damage, speeds, AI, economy), or stored replays re-simulate under new rules and silently play back different runs than their recorded scores claim; a version-mismatched replay shows "replay unavailable" (a sticky `watchErr` notice — the death hud repaints every tick, so one-shot `hud.innerHTML` writes get clobbered). `grantLevelToken` runs off the in-memory `runMaxwave` so replays re-grant tokens identically. The recorder caps at 50k events (`recOverflow` — marathon runs just don't ship a replay) and `lbSubmit` attaches `{replay}` when it fits 150KB. The worker stores it as its **own item** `rp#sf#<rid>` (rid = the verified run token's id; displaced entries' replays are deleted eagerly; daily replays expire with their board (4-day TTL), all-time replays get a 90-day backstop). `validateReplay` (exported for tests) is a **strict per-opcode schema, not just a size cap** — this is what keeps the endpoint useless as free hosting: event ticks must be non-decreasing and bounded by the proof-verified run length, per-tick event density is capped at human rates (12), masks are one byte, args are tiny enums, and upgrade ids must match `^[a-z0-9_]{1,24}$` (no free-form strings anywhere); invalid replays are silently dropped — never fatal to the score. Combined with the top-10 qualification gate + single-use run tokens, worst-case attacker-persistable data is hard-ceilinged at ~8 MB total (≤10 all-time + ≤10/day×4d daily replays at ≤160KB). **Recording stamp rule:** in-tick inputs are recorded at pend consumption with the current tick; **between-tick UI events (buy/continue/intro-advance/Ian) are stamped `tick + 1`** so the feeder applies them in the same between-ticks slot they happened in — stamping them with the current tick replays them one tick early and can shift tick-based cooldowns. The board entry carries `rp`. **Watching:** board rows with a stored replay show ▶; on the death screen **W opens the picker** (↑↓ choose, Enter watch, Q/W close — Escape is avoided in-game because it's the XP desktop's shutdown key). `startWatch` fetches `GET /replay?id=`, `startReplay` saves the watcher's own intro selections (`repSaved`), impersonates the recorded setup (classes, coop, `sfSeedOverride = seed`), and re-inits; the **replay feeder** at the top of `loop()` applies events stamped ≤ the current tick — masks land before the input sampler (which reads `repMask` instead of `keys` when `replayMode`), pend actions land where the pend consumer eats them, and menu/cutscene events replay through the same functions (`buyUpgrade`/`finishUpgrades`/`advanceBossIntro`/`chooseIan`) in the same between-tick slot — so the sim replays **bit-exactly**. While `replayMode` is true, **nothing of the watcher's changes**: `saveUpgrades`/`saveTokens`/maxwave writes/local-best/`lbBegin` are gated, and `unlockAchievement` is wrapped at the bridge destructure (`_unlockAch`) to no-op. `endRun` in a replay shows "so ends the legend of …"; **Q** anywhere in a replay calls `stopReplay()` (restores the watcher's selections, back to the title). onKey swallows all other input during a replay. **Cheat runs are unranked client-side**: any warp/grant cheat (`nine`, 9-spam, 8-spam) sets `cheated`, `lbBegin()` skips the board entirely, and the death screen says so. The backend stores each board in one DynamoDB item (`pk=lb#sf` all-time; `pk=lb#sf#YYYYMMDD` per day, written with a `ttl` so old days expire; `day` must be today/yesterday UTC server-side or the request is rejected) and needs no Turnstile (Origin allowlist + per-IP rate limits — including one on `/run-start` — + server-side clamping + the run proof above). A submit that wouldn't crack its top 10 is **never written** (only genuine top-10s are ever stored, so the endpoint can't be abused as free key/value storage). Backend routes (`/scores`, `/scores?day=`, `/run-start`, `/score`, and the netplay signaling `/mp-host` / `/mp-offer` / `/mp-join` / `/mp-answer`) live in `~/hal-worker`. **Frame driver (fixed timestep):** `loop()` no longer self-schedules — `frameStep(ts)` (the rAF callback) accumulates **wall-clock time** from the rAF timestamp into `simAcc` and advances the sim at `SIM_HZ × SF_SPEED` ticks per second **independent of the display's refresh rate** (a 120 Hz monitor renders more often but simulates no faster). The accumulated `dt` is capped at 0.25s and steps at 5 per frame, so a backgrounded tab or hitch drops ticks instead of fast-forwarding or spiraling. `loop()` = one sim tick + one render, fused — so `rnd()` consumed in render code still runs exactly once per tick (if render is ever decoupled from the sim, every `rnd()` in draw code must move into the sim first). `SF_SPEED` is 1.0 on localhost / `file:` (dev) and **1.1 when deployed** (66 ticks/s), so the live game runs ~10% faster than local. **Determinism (groundwork for replays / future lockstep MP):** the sim is a pure function of `(seed, inputs)` — all gameplay randomness goes through a seeded mulberry32 PRNG (`rnd()`, seeded per run in `init()` from `sfSeed`; a future MP layer pins a shared seed via `sfSeedOverride`) instead of `Math.random()`, and timing runs off a monotonic `tick` counter (advanced once per `loop()`, `SIM_HZ` 60) instead of the wall clock.
