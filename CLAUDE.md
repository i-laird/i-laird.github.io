# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview
Single-page terminal-style portfolio site hosted on GitHub Pages. No build system, no framework, no dependencies — hand-written files: `index.html` (markup), `style.css`, `app.js` (the core terminal), the pure `lib/` helpers, and eight lazy-loaded chunks fetched on first use (see Architecture): `stickfighter.js` (the Stick Fighter 2000 game — a **generated artifact** assembled from the `stickfighter/` part files by `scripts/assemble-sf.js`; edit the parts, never the artifact — see Architecture), `games.js` (the four shell games — racecar/snake/pong/2048), `sans.js` (the sans easter egg), `chess.js` (the chess game), `halllm.js` (the experimental LLM HAL), `desktop.js` (the XP desktop behind `gui`), `achui.js` (the achievements overlay + share card), and `room.js` (the CSS-3D bedroom behind `room`). Pre-recorded HAL 9000 audio clips live in `assets/audio/` (~135 mp3 files generated via ElevenLabs), alongside music tracks and `sans_voice.mp3`. To regenerate clips, run `./generate_hal_audio.sh` (requires ElevenLabs API key set in the script).

## Deployment
Push to `main` branch → auto-deploys via GitHub Pages. The `.nojekyll` file disables Jekyll processing.

**Service worker (`sw.js`):** GitHub Pages serves everything with `Cache-Control: max-age=600` (not configurable), so `sw.js` provides repeat-visit caching: **cache-first** for `assets/audio/*` (a played HAL clip or music track never re-downloads; audio is fetched by URL so Range requests still cache the full file) and **stale-while-revalidate** for every other same-origin GET (the JS bundle + lazy chunks, HTML, CSS — a returning visitor gets the previous build once after a deploy, the new one on the next load; safe because the chunk entry names + api bridge keys are stable across builds). Cross-origin (CDNs, Turnstile, the hal-worker API) and non-GET requests are never intercepted. Registered at the bottom of `app.js` after `load`, **skipped on localhost/http** (dev stays cache-free). It ships unobfuscated (copied through in `build.js`'s `STATIC` list; `verify-build` asserts it's present). **Bump `VERSION` in `sw.js` to flush all caches on a breaking deploy.** `test/sw.test.js` runs the real file in a stubbed SW environment and pins the routing contract.

## Obfuscated build (optional, for hiding easter-egg secrets)
The site is normally served as the clean hand-written source. `npm run build` (`scripts/build.js`) produces a `dist/` whose JS is obfuscated gibberish — for deploying a build whose secrets (the hunt logic, decrypt puzzle, HAL, finale) aren't trivially readable or paste-into-an-LLM-able. **It's opt-in: the clean source stays the source of truth, `npm run serve` serves it directly, and all tests run against it, not the build.** `dist/` is gitignored. The deploy topology (private source → push `dist` to the public Pages repo) is intentionally left to the operator — `build.js` only produces the artifact.
- **Topology:** `dist/app.js` = `lib/*.js` + `app.js` concatenated, wrapped in ONE IIFE, obfuscated **heavily** (control-flow flattening, dead code, string-array). lib must bundle with app.js (it reads `_djb2`/`_xorDecode`/`_alignTimings`/`_halNorm`/`makeRng` plus the `lib/shell.js` parsers). The eight lazy chunks — `dist/stickfighter.js`, `dist/games.js`, `dist/sans.js`, `dist/chess.js`, `dist/halllm.js`, `dist/desktop.js`, `dist/achui.js`, `dist/room.js` — are each wrapped in their own IIFE and obfuscated **lightly** (identifier mangling + plain string relocation, **no control-flow flattening** — the game chunks run frame loops and the others are small UI shells; one config keeps them uniform). They're separate chunks because each reaches app.js only through its `api` bridge. `dist/index.html` collapses the six lib+app `<script>` tags to one `app.js`.
- **Why the IIFE wrap:** obfuscators leave true globals alone; wrapping makes the top-level names function-scoped so they get renamed. This is why app.js exports its 4 inline-handler functions to `window` and each chunk exports its entry (`openStickFighter` / `initGames` / `initSansMode` / `initChess` / `initHalLLM` / `initDesktop` / `initAchUI` / `initRoom`) via an explicit `window.<name> =` line (see Architecture) — those survive the wrap.
- **Config invariants (in `build.js`):** `renameProperties`/`transformObjectKeys` **OFF** (worker JSON fields, DOM props, the `api.*` keys, and `window.<fn>` exports are literal property names); the chunk entries `openStickFighter`/`initGames`/`initSansMode`/`initChess`/`initHalLLM`/`initDesktop`/`initAchUI`/`initRoom` reserved on both sides (each lazy-load handshake crosses its chunk boundary by that name); no source maps.
- **`npm run verify-build`** (`scripts/verify-build.js`, run after build): boots the real obfuscated bundle in jsdom (asserts the terminal comes up + the public API survived — catches obfuscation breakage that "it parses" misses), drives the obfuscated game chunk headlessly with a fixed seed and times it against the clean source (asserts the light config kept overhead negligible — empirically the game runs ≈ the same or slightly faster, since `simplify`/`compact` offset the near-zero mangling cost), then executes `dist/games.js`, `dist/sans.js`, `dist/chess.js`, `dist/halllm.js`, `dist/desktop.js`, `dist/achui.js`, and `dist/room.js` and asserts each still exports its `window.<entry>` and returns the handler keys app.js calls.

## Testing
`npm test` runs `node --test` over `test/`. CI (`.github/workflows/ci.yml`) runs `npm run check` = lint (ESLint) + lint:html (html-validate) + format:check (Prettier) + test. Two kinds of tests:
- **Pure-helper unit tests** (`test/codec.test.js`, `timing.test.js`, `text.test.js`, `rng.test.js`, `shell.test.js`) cover the dual-mode `lib/*.js` helpers (they `module.exports` for Node and define browser globals for the page). Logic worth testing is best extracted into a `lib/` helper so it can be unit-tested without a DOM. `lib/rng.js` (seeded mulberry32 PRNG + `hashSeed`) is the determinism foundation for Stick Fighter — `rng.test.js` pins the algorithm so saved seeds/replays can't silently break. `lib/shell.js` holds the terminal's pure shell parsers (tokenizing, globs, pipe filters grep/head/tail/wc, history `!`-expansion, `$VAR` expansion, path resolution, the session-overlay `mergeNode`); the state-reading ones take `cwd`/`cmdHistory`/home as parameters, and app.js keeps thin same-named adapters (`fsResolve`/`fsDisplay`) or passes the state at call sites.
- **Boot smoke test** (`test/boot.test.js`, uses `jsdom`) loads the real `index.html` + the real `lib/*.js` → `app.js` script chain into a jsdom DOM, runs `boot()`, and asserts the terminal comes up, the inline-HTML global handlers exist, `help` dispatches, output reaches `#a11y-live`, and the global error boundary recovers a wedged terminal (it dispatches a synthetic `error` event and checks the prompt is restored). This catches the load-time `ReferenceError` class that linting can't — important because `app.js` is one no-IIFE classic script where every top-level name shares one global scope. It shims the few browser APIs `app.js` uses unguarded at load (`Audio`, `fetch`, canvas `getContext`); `matchMedia`/`AudioContext`/`speechSynthesis` are left undefined on purpose to exercise the real feature-guards. Each test calls `dom.window.close()` (via `t.after`) to stop jsdom timers — without it the `showEggNudge` 60s timeout keeps the process alive.
- **Stick Fighter determinism** (`test/stickfighter-determinism.test.js`, uses `jsdom`) drives the real game headlessly (recording-canvas context that folds every draw op into a rolling hash **plus per-tick chunk hashes split on each full-screen clearRect**, manual `requestAnimationFrame` pump with configurable frame cadence, fixed seed via stubbing the `init()` entropy draw) and pins four properties: a run is reproducible from its seed (same seed → identical draw stream); a different seed diverges (proving the stream reflects RNG-driven gameplay); **60 Hz and 120 Hz pumps over the same wall-clock span produce the identical tick stream** (chunk-by-chunk equal, totals within the one boundary tick — guards the fixed-timestep driver); and **`reduceMotion` does not change how many `rnd()` draws the sim makes** (via an instrumented `makeRng` in the stub bridge — guards settings-independent RNG consumption). It builds a stub `api` bridge to launch the game (see Architecture).
- **Stick Fighter netplay** (`test/stickfighter-netplay.test.js`, uses `jsdom`) boots **two complete instances** of the real page + game, stubs WebRTC with a synchronous loopback (StubPC/StubChannel through a shared world object) and the four `/mp-*` signaling routes with an in-memory room map, then drives one intro to HOST and the other to JOIN (typing the room code — which deliberately contains a `Q`, pinning that code entry doesn't treat it as back-out). It asserts the handshake starts both sims, that **1500 frames of divergent-input lockstep never trip the game's own 60-tick checksum tripwire** (a desync boots back to the intro, so "both still in the run" is the two-machine determinism proof), that an online run writes **no** localStorage (best/trophies/tokens/upgrades/maxwave), and that killing the transport does NOT end the run — both peers hold the frozen run, re-signal through the derived rejoin room, resume, and keep lockstepping (then a deliberate Q exit lands both on the intro). Real timers (the 2s answer poll + the 2–2.5s reconnect polls), so it takes ~10–20 seconds.
- **Four-player war band** (`test/stickfighter-warband.test.js`, uses `jsdom`) boots FOUR full instances over a unique-SDP multi-connection stub: one room code seats a host + three joiners (minted room, then the host-armed slot rooms), no input frames flow before the whole band readies up, four seat-ordered boon picks, 1200 frames of divergent four-seat lockstep under the checksum tripwire, and one Q disbands all four to the intro. Real timers, ~15–30s.
- **Dragoon joust rule** (`test/stickfighter-dragoon.test.js`, uses `jsdom`) drives a real dragoon run purely through the keyboard (class row → begin → boon → a flapping patrol): asserts the galloping lance racks up kills while the rider lives, and that a standing dragoon dies to the first contact — the class's skewer-or-die contract, end to end.
- **Wyrm & Rider pair** (`test/stickfighter-wyrm.test.js`, uses `jsdom`) drives a couch co-op run on one keyboard: the paired class pick binds P2 to the rider, the galloping wyrm racks up trample kills while both seats live, and releasing every key collapses the pair to the death screen.
- **Chunk isolation** (`test/stickfighter-isolation.test.js`, `games-isolation.test.js`, `sans-isolation.test.js`, `chess-isolation.test.js`, `halllm-isolation.test.js`, `desktop-isolation.test.js`, `achui-isolation.test.js`, `room-isolation.test.js` — pure static lint, no DOM) enforces that each lazy chunk references no app.js/lib global by free name (everything via its `api` bridge), so each stays independently bundle/obfuscate-able. Lints the file alone with `no-undef` + browser globals only; any flagged name must be routed through the matching bridge (`sfBridge()` / `gamesBridge()` / `sansBridge()` / `chessBridge()` / `halLLMBridge()` / `desktopBridge()` / `achBridge()` / `roomBridge()`).
- **Stick Fighter assembly freshness** (`test/stickfighter-assembly.test.js`, pure file compare — no DOM): the committed `stickfighter.js` must byte-equal `assemble()` over the `stickfighter/` parts (see Architecture), every `.js` file in `stickfighter/` must match the `NN-*.js` pattern the assembler picks up, and the artifact must keep the `window.openStickFighter` export + generated-file header. Fails CI on a stale artifact or a direct edit to it.
- **Achievement integrity** (`test/achievements.test.js`, pure file parsing — no DOM) guards the easter-egg count from silent drift: ids are unique, the count baked into `generate_og_image.sh` ("N easter eggs") matches `ACHIEVEMENTS.length`, and every literal `unlockAchievement('id')` call site (across `app.js`, the lazy chunks, and `index.html`) references a defined id. Dynamic calls (`unlockAchievement(data.ach)` etc.) are excluded since they resolve at runtime. **When you add/remove an achievement, re-run `./generate_og_image.sh`** or this test fails.

## Architecture
`index.html` is bare markup (~100 lines); the core terminal lives in `app.js` (~3,700 lines), loaded as a classic script at the end of `<body>`. It must stay a classic script (not a module): the inline `onclick` handlers in `index.html` (`toggleSound()`, `focusCmd()`) rely on its top-level functions being globals, and the element lookups at the top of the file rely on the DOM existing. **app.js is NOT wrapped in an IIFE** — its top-level `const`/`let`/`function` declarations sit in the shared global lexical scope, which is what lets the lazily-loaded chunks (separate classic scripts) find their `window.<entry>` handshake. Eight feature areas are **not** in app.js — each lives in its own lazily-fetched chunk behind an explicit `api` bridge (see the sections below): `stickfighter.js` (Stick Fighter 2000), `games.js` (the four shell games), `sans.js` (the sans easter egg), `chess.js` (chess), `halllm.js` (the experimental LLM HAL), `desktop.js` (the `gui` XP desktop, which also hosts the Stick Fighter loader), `achui.js` (the achievements overlay + share card), and `room.js` (the `room` CSS-3D bedroom). The bridge pattern is identical across all of them: app.js builds an `api` object (`gamesBridge()` / `sansBridge()` / `chessBridge()` / `halLLMBridge()` / `desktopBridge()` / `achBridge()` / `roomBridge()` — `sfBridge()` lives inside desktop.js and re-exposes desktopBridge values) whose keys are the stable contract — stable functions/elements are plain keys the chunk destructures, runtime-varying flags are getters (and setters where the chunk writes back, e.g. `activeMusic`, `sansBattleActive`, `awaitingInput`); the chunk references nothing from app.js by free global name (statically enforced per chunk by the isolation tests). The pure shell parsers (tokenizing, globs, pipe filters, history/`$VAR` expansion, path resolution, `mergeNode`) live in `lib/shell.js` — see Testing. Key sections:

**Lazy-loaded Stick Fighter (`stickfighter.js`, assembled from `stickfighter/`):** the ~8,000-line game ships as one lazy chunk whose **source is the 23 `stickfighter/NN-*.js` part files**, concatenated in filename order inside the single `function openStickFighter(xp, api) { … }` closure by `scripts/assemble-sf.js` — **edit the parts, run `npm run assemble`, commit both**; never edit `stickfighter.js` directly (`npm run serve`/`build` assemble automatically, and `test/stickfighter-assembly.test.js` pins the committed artifact to the parts, so drift or direct edits fail CI). Fetched on demand the first time the desktop icon is opened: `launchStickFighter()` (inside the `desktop.js` chunk's `launchXP` closure) injects `<script src="stickfighter.js">` once (guarded by a `sfLoading` promise + a `typeof window.openStickFighter` check), then calls the global `window.openStickFighter(xp, api)` it defines — a chunk-to-chunk handshake, which is why both entries are reserved names. Every app.js/lib dependency arrives through the explicit `api` bridge built by `sfBridge()` in desktop.js (re-exposing app.js's `desktopBridge()` values): `unlockAchievement`, `_chirp`, `makeRng`, `HAL_WORKER_URL`, live `soundEnabled`/`reduceMotion` getters, and an `activeMusic` getter/setter. The game references **nothing** from app.js by free global name — `test/stickfighter-isolation.test.js` statically enforces this on the assembled artifact; add a key to `sfBridge()` (and `desktopBridge()` if app.js must supply it) if it ever fails. The desktop is passed in as `xp`; the running game parks its teardown on `xp._sfCleanup` so the desktop's `shutdown()` (ESC) can stop it. Keep the assembled chunk a classic script. **Everything else about the game — mechanics, classes, bosses, netplay, replays, economy, trophies, determinism rules — is documented in `stickfighter/CLAUDE.md` (auto-loaded when `stickfighter/` files are touched); read it before editing the game.**

**Lazy-loaded shell games (`games.js`):** `createGameShell` and the four shell-game commands (racecar / snake / pong / 2048, ~1,400 lines) live in `games.js`, fetched on demand the first time one is launched. The `COMMANDS` entries in app.js are one-line stubs calling `launchGame(name)`, which injects `<script src="games.js">` once (guarded by a `gamesLoading` promise + a `typeof initGames` check), calls the global `initGames(api)` it defines (with `gamesBridge()`: `appendNode`/`blank`/`scroll`/`halSpeak`/`halD`/`unlockAchievement`/`_chirp` + the `inputRow`/`cmd` elements, plus live `godmodeUnlocked`/`playerName` getters), caches the returned `{racecar, snake, pong, '2048'}` handlers, and dispatches. A load failure prints an error line and resets `gamesLoading` so retyping the command retries. `chess` is NOT in this chunk (it doesn't use the shell; it stays in app.js). When editing these games, edit `games.js`, not `app.js` — and keep its original indentation (multi-line string screens).

**Lazy-loaded sans mode (`sans.js`):** the whole Undertale easter egg — `activateSansMode`, the out-of-battle command set, and the ~700-line persistent battle — lives in `sans.js`, fetched on demand when the mode is first summoned: the `sans` command **prefetches it during HAL's long speech** (so it's loaded by CONFIRM time; `showSans()` then goes through `loadSansMode().then(...)` with `sansLoadFailed()` as the error path), and `sss` loads it directly. `initSansMode(api)` returns `{ activate, command, battleCommand }`; app.js's `sansMode` dispatch block routes typed input to `sansHandlers.command(token, raw)` (or `.battleCommand(token)` during a battle) — safe because `sansMode` can only become true after the chunk's `activate()` ran. **The mode flags stay owned by app.js**: `sansMode` and `sansBattleActive` are app.js globals (read by the dispatcher, `getPromptHTML`, the finale idle-poll, `resumeModeAudio`, and the Konami handler); the chunk reads/writes them through `sansBridge()` accessors, and writes `activeMusic` the same way so the sound toggle reaches the battle music. `sansChirp`/`chirpTypeLine`/`showConfirmOverlay` stay in app.js (the `sans`-command speech/handoff and the Konami dirty-hacker response use them app.js-side) and are passed through the bridge; `sansBattle`/`sansDeaths` moved into the chunk. When editing sans content, edit `sans.js`, not `app.js` — and keep its original indentation.

**Lazy-loaded chess (`chess.js`):** the chess game (~230 lines) lives in `chess.js`, fetched on demand the first time `chess` (or HAL mode's `play chess`) is run — the `COMMANDS.chess` entry is a stub calling `launchChess()`. `initChess(api)` returns `{ chess }`; `chessBridge()` carries the output helpers + `inputRow`/`cmd`, live `halMode`/`godmodeUnlocked`/`soundEnabled`/`playerName` getters (difficulty tier and quips are chosen per launch), and **`awaitingInput`/`silentInput`/`activeMusic` accessors the chunk writes back through** — typed moves flow from app.js's Enter handler into the chunk via the `awaitingInput` callback, so that flag must stay app.js-owned. The chess.js/Stockfish CDN loading is unchanged inside the chunk; the CDN engine global is deliberately referenced as `window.Chess` (a bare `Chess` would fail the isolation lint). When editing chess, edit `chess.js`, not `app.js`.

**Lazy-loaded LLM HAL (`halllm.js`):** the whole experimental "escape the terminal" mode — the CONFIRM overlay, Turnstile loading + bot gate, session/turn networking, the meters HUD, and the win/lose/broken endings (~400 lines) — lives in `halllm.js`, fetched on demand when a player picks **[2]** at the `hal` prompt (the two-HAL menu **prefetches it** while the player reads, so it's usually loaded by choice time; `halLLMLoadFailed()` is the error path and resets the loader for retry). `initHalLLM(api)` returns `{ showInfoPage, handleInput }`; app.js's dispatcher routes typed input to `halLLMHandlers.handleInput(raw)` — safe because `halLLM` can only become true after the chunk's `startHalLLM` ran. **The mode flags stay owned by app.js**: `halMode`, `halLLM`, and `halLLMBusy` are app.js globals (the dispatcher reads them; `restoreNormal` resets them); the chunk writes them through `halLLMBridge()` accessors. The per-session state object (`halLLMState`) moved into the chunk. `halAskNameAndSound` stays in app.js (shared with the classic HAL) and is passed through the bridge; `halEyePre` and the Turnstile loader moved in (the Turnstile global is deliberately read as `window.turnstile`). `daisy`/`clear` cross the bridge as wrapper functions around the `COMMANDS` entries. When editing the LLM HAL, edit `halllm.js`, not `app.js`.

**Lazy-loaded XP desktop (`desktop.js`):** the fake Windows-XP desktop behind `gui` — bliss wallpaper, icons, taskbar, start menu, and the Stick Fighter lazy-loader (~250 lines) — lives in `desktop.js`, fetched on demand the first time `gui` runs; `COMMANDS.gui` is a stub that unlocks the `desktop` egg (unless auto-launched) and calls `launchDesktop()`. The mobile auto-launch (`COMMANDS.gui(true)`) goes through the same stub. `initDesktop(api)` returns `{ open }`; `desktopBridge()` carries `cmd`/`openUrl`/`unlockAchievement` for the desktop itself plus everything `sfBridge()` (now inside this chunk) re-exposes to Stick Fighter: `_chirp`, `makeRng`, `HAL_WORKER_URL`, and live `soundEnabled`/`reduceMotion`/`activeMusic` accessors. When editing the desktop, edit `desktop.js`, not `app.js`.

**Lazy-loaded achievements overlay (`achui.js`):** the easter-egg panel behind the titlebar 🥚 badge — the unlocked/locked list, the share view, and the 1200×630 share-card canvas (~260 lines) — lives in `achui.js`, fetched on demand the first time the badge is clicked; `toggleAchievements()` in app.js is the loader stub (it stays app.js-side and window-exported because the badge's inline `onclick` calls it by name, and it still dismisses the egg nudge before loading). `initAchUI(api)` returns `{ toggle }`; `achBridge()` carries `ACHIEVEMENTS`, the live `foundEggs` set, `cmd`, and an **`achOverlayEl` accessor — that element handle stays owned by app.js** because `tryStartFinale` polls it to avoid interrupting an open overlay. `unlockAchievement`/`syncEggBadge`/`eggToast`/`showEggNudge` stay in app.js (they're called from everywhere, including the other chunks' bridges). When editing the overlay or share card, edit `achui.js`, not `app.js`.

**Lazy-loaded room (`room.js`):** the `room` command's camera pull-back that reveals the CRT monitor the terminal runs on — a pure CSS-3D late-90s bedroom at 2 AM (~250 lines JS + a large style.css section, `.rm-*` / `#room-*`), no WebGL, no library. Fetched on demand the first time `room` runs; `COMMANDS.room` is a stub that gates on viewport size (needs ≥720×480), unlocks the `the-room` egg, and calls `launchRoom()`. `initRoom(api)` returns `{ open }`; `roomBridge()` carries `winEl` (the live `.window` element), `cmd`, output helpers, `unlockAchievement`, `_chirp`, live `soundEnabled`/`reduceMotion`/`achOverlayOpen` getters, and a **`roomActive` accessor — the flag stays app.js-owned** because `tryStartFinale` reads it (the finale must not fire over the room). Mechanics: `open()` reparents the LIVE `.window` onto the monitor's screen face (`#room-screen`, at world origin z=0; restored to its exact body position on exit), adds `body.room-view` (which hides the viewport-level CRT glass — the monitor prop has its own `.rm-glass` — and makes `.window` `pointer-events:none` so clicks belong to props), and animates `#room-world`'s transform from a JS-computed zoomed-in framing (`tz = P·(1−1/s)`, P must match the CSS `perspective: 1050px`) to the starting camera, masked by a `.rm-blink` black flash. **The room is a walkable FPS**: the camera is a position + yaw/pitch (`CAM_START`/`cam` in room.js; world transform = view matrix `translateZ(P) rotateX(pitch) rotateY(yaw) translate3d(-x,-y,-z)`; in this convention yaw+ looks RIGHT and pitch+ looks UP). **The mouse looks by dragging** (deliberately NO Pointer Lock — an earlier version locked on the first click, which made every prop unclickable with the cursor gone; `user-select:none` + preventDefault keep drags from selecting text, and a click at the end of a >8px drag is suppressed via `dragDist` so look-drags never trigger props). W/S or Up/Down walk, A/D strafe, Left/Right arrows turn (keyboard-only users can still steer); all dt-scaled in a rAF loop that starts once the fly-out lands (`arrive()` puts `#room-world` in `.no-anim` so per-frame camera writes don't fight the transition; `exit()` re-enables it to glide back). Box collision (`BOUNDS`/`BLOCKS`) keeps the player inside the walls and out of the desk, tower, dresser, bed, and chair, with axis-sliding along obstacles. Escape/Enter or clicking the screen exits; **props are decorative (tooltips only)** except the lava lamp (toggles `.room-lit` warm lighting) and the room's ONE `data-egg` hotspot — the HAL poster (`watched-back`) — which unlocks via the bridged `unlockAchievement` (dynamic call: `unlockAchievement(el.dataset.egg)`). The mug is printed "I ♥ CLAUDE". Mouse-look is folded into the camera transform itself (lerped view-space yaw/pitch offsets consumed by the rAF loop — `#room-par` is structural only), and the view matrix leads with `translateZ(P)` so rotation pivots at the EYE, not at a point P in front of it (see `viewPrefix()` in room.js — without it turning orbits the room and walked-past planes render mirrored). The room is a sealed, furnished box: the front wall (`.rm-front`, `rotateY(180)` so its content faces inward) carries a real-scale door, a dresser, and a Snellen eye chart; the right wall a pinned corkboard and the bed (headboard/side/foot/top planes, gamepad on the blanket); plus curtains around the window, a ceiling light that warms with `.room-lit`, baseboards on every wall, and a desk chair. Furniture is **boxified** (tower/monitor/desk/dresser/clock/headboard have closing faces so oblique views read solid), and roundish props (mug, lava lamp, trophy — elements with `data-bx/by/bz`) are **sprite billboards**: `updateBills()` in the rAF loop rewrites their transform to `rotateY(-cam.yaw)` so they always face the camera instead of vanishing edge-on. Reduced motion swaps the camera fly for a cut (walking stays enabled since it's user-driven). **The creep**: the longer a visit runs, the less alone it feels — staged by `armCreep()`/`setCreep()` in room.js (`creep-1..4` classes on the viewport; ## HAL audio system
- **`halPlayKey(key)`** — plays `assets/audio/${key}.mp3`. Returns a `Promise` that resolves on `onended`/`onerror`, so sequential HAL lines can be chained with `.then()` rather than fixed `setTimeout` delays. When `soundEnabled` is false, returns `Promise.resolve()` immediately.
- **`halSpeak(text)`** — normalizes text via `_halNorm()` (strips `HAL:` prefix, strips player name from surrounding punctuation, expands em-dashes), looks up the result in `HAL_CLIPS`, and calls `halPlayKey`. Falls back to browser TTS for any text not in the table.
- **`HAL_CLIPS`** — lookup table mapping normalized text → clip filename. ~100 entries covering all fixed HAL lines across all games and interactions.
- **`halTypeLine(text, clipKey)`** — typewriter effect synced to ElevenLabs per-character timing data (`assets/audio/hal_timing.json`, loaded into `HAL_TIMING`). `_alignTimings()` LCS-aligns clip characters to display text so injected player names don't break sync. Falls back to a `currentTime/duration` loop if timing isn't loaded, or a fixed-rate typewriter when sound is off.
- **Sans chirps** — `chirpTypeLine(text, chirpFn, msPerChar)` types text with a per-character sound; `sansChirp` clones `sans_voice.mp3`, `halChirp` is a WebAudio sine blip.
- **When adding a new HAL line:** if it's a fixed string, add an entry to `HAL_CLIPS` and generate the clip with `generate_hal_audio.sh`. If it contains player name, the normalized key should have the name stripped (handled automatically by `_halNorm`). Call `halPlayKey(key)` directly at the call site rather than `halSpeak(text)` when the key is known.
- **Sequential lines** (SSH, godmode Konami sequence): chain via `.then()` on `halPlayKey`, not `setTimeout`.

## LLM HAL — "escape the terminal" (experimental, opt-in)
A second, optional HAL: a live language model role-plays HAL trying to stop you from leaving. **The scripted HAL above is untouched** — this only runs when `halLLM` is true. The whole mode lives in the lazy `halllm.js` chunk (see Architecture) — edit it there; app.js keeps only the flags, bridge, and loader. Flow: `hal` → choose **[2]** (prefetched at the menu; loaded via `loadHalLLM()`) → `showHalLLMInfoPage()` → `showHalLLMConfirmOverlay()` (a full-screen red CONFIRM gate stating it's LLM-based, the escape-game rules, and a misuse warning; type CONFIRM to proceed / Escape to back out) → `askHalLLMName()` (name + optional voice) → `startHalLLM()` (sets `halMode` **and** `halLLM`, red theme, cold open, prints the meter HUD). The website is the renderer; a **separate backend service is the brain** (AWS Lambda + API Gateway + DynamoDB, in `~/hal-worker`; base URL `HAL_WORKER_BASE`, overridable via `localStorage.ilaird_hal_worker`).
- **Bot gate (Cloudflare Turnstile + session handshake):** `startHalLLM()` first calls `halLLMOpenSession()` → `getTurnstileToken()` runs an invisible Turnstile challenge (script in `index.html`, `TURNSTILE_SITE_KEY`; widget renders inline so a rare interactive challenge is completable) → POSTs `{tsToken}` to `POST {base}/session`, which returns a short-lived signed `sessionToken` stored in `halLLMState.sessionToken`. `halLLMBusy` stays true during the handshake; failure (no token / unreachable) → `halLLMEndBroken()`. Subsequent turns carry the `sessionToken`; no per-turn challenge. The backend (not the browser) holds the Anthropic key and enforces per-IP rate limits + a daily cap.
- **Game:** two meters — `escape` (0→100) and `control` (0→100). **State is server-authoritative:** the meters, turn counter, rolling history, and revoked-word list live in a short-TTL DynamoDB item keyed to the session (`halgame#<jti>`, `~/hal-worker/src/index.mjs`), not the browser. Each turn `handleHalLLMInput()` POSTs only `{playerName, message, sessionToken, voice}` (`voice` = `soundEnabled`) to `POST {base}/turn` and expects JSON `{reply, escape, control, event?, outcome:"ongoing"|"escaped"|"caught", demand?, revoke?, audio?, alignment?}`, then prints `event` (dim), redraws the HUD (`renderHalMeters()` — per-line `▰▱` bars) from the returned meters. `halLLMState` on the client holds only display copies of `escape`/`control` (seeded from `/session`, which returns the starting values) plus a local echo of `revoked` for instant input rejection; there is no client-side turn counter or history. `escaped`/escape≥100 → `halLLMWin()` (`outsmarted-hal` egg). `caught`/control≥100 → `halLLMLose()` (`disconnected-by-hal` egg). Both end with `restoreNormal()`. The worker deletes the state item the moment the game ends and lets it self-expire (`HAL_STATE_TTL_SECONDS`, default 20 min) if abandoned.
- **Session personality & pressure moves:** the worker derives a stateless per-session plan from the session token's `jti` (`sessionPlan()`): a hidden **weakness** (one of `WEAKNESSES` in `prompt.mjs`, injected into each turn's bracketed metadata — never the cached system prompt — and never revealed; genuinely striking it earns 25-35 ESCAPE) plus scheduled turns where HAL **demands an answer** (the `demand` field — the client prints it as a red `⬤ HAL demands an answer:` line; the worker appends it to HAL's stored history entry so the prompt punishes evasion next turn) or **revokes a word** (the `revoke` field — server-validated by `validateRevoke()` to be a real word the player typed, never their name/`daisy`/`clear`/`confirm`/an already-revoked word, capped at 3). Revocations are enforced **server-side** (a banned word gets a scripted rebuke with no model call and no state change); the client also mirrors up to 3 in `halLLMState.revoked` and rejects them locally for instant feedback, without a network trip. Both fields are stripped on non-scheduled turns and cleared on every guard/judge termination.
- **Terminal degradation:** `applyHalGrip()` in `halllm.js` deepens the red theme as CONTROL crosses 50/70/85 (`HAL_GRIP_TIERS` — cumulative overrides of the same CSS variables `applyTheme` manages, so `restoreNormal()` clears them however the game ends) and plays a low double-thump heartbeat via the bridged `_chirp` at 70+ (audio-only; no motion, so no `reduceMotion` gate needed).
- **Voice (optional, sound-gated):** the client sends `voice: soundEnabled`, so the backend only synthesizes when the player has sound on. When the backend returns `audio` (base64 mp3), `playHalVoiceLine()` plays it and reveals "HAL: …" synced to `alignment` (ElevenLabs per-character timings, via the same `_alignTimings` LCS used for scripted clips), tracked through `halAudioEl` so the sound toggle's `stopAllAudio()` can stop it. No audio → `halTypeLine()` types at a fixed rate (+ browser TTS if sound on). Backend voice = ElevenLabs **Flash** (`eleven_flash_v2_5`) in the scripted-HAL voice (`ki9mNgaTTZJesOJj7cZB`) via the `/with-timestamps` endpoint, gated by a **separate low daily cap** (`VOICE_DAILY_LIMIT`, default 20, its own DynamoDB counter); over-cap or any TTS failure just omits `audio`. Disabled entirely if `ELEVENLABS_API_KEY` is unset. The mode's **static lines** (cold open `hal_llm_open`, and `hal_llm_win`/`hal_llm_lose`/`hal_llm_broken`) are pre-recorded clips like the scripted HAL — generated by `generate_hal_audio.sh` (canonical name "Dave", re-synced per player via `_alignTimings`) and passed to `halTypeLine(text, clipKey)`; only the live per-turn replies use the backend TTS path.
- **In LLM mode the dispatch is simple** (`if (halLLM)` branch at the top of `submitCommand`'s `halMode` block): only `daisy` (bail) and `clear` are commands; **everything else routes to the model** — typing `open pod bay doors`, `sudo disconnect hal`, etc. *is* the gameplay. `halLLMBusy` locks input during a request; `halLLMShowThinking()` shows a "HAL is considering you…" indicator (static under `prefers-reduced-motion`).
- **No offline mode by design:** if the worker is unconfigured, unreachable, times out (15s), or returns anything malformed (`halLLMRequest()` validates shape), the session ends in character via `halLLMEndBroken()`.

## Games
The four shell games (racecar / snake / pong / 2048) are self-contained closures in the lazy `games.js` chunk (see Architecture — their `COMMANDS` entries are `launchGame()` stubs), built on **`createGameShell({ hint, lineHeight, halMsg, onKeyDown, onKeyUp })`** (also in `games.js`) — it creates the wrap/screen/hint DOM, hides the input row, and registers key listeners; the optional `halMsg: 'top' | 'bottom'` adds a HAL message line auto-spoken via MutationObserver. It returns `{ wrap, screen, halMsgEl, end, after, every, cancel }`; the game's own `end()` does game-specific teardown (intervals, timers) then calls `shell.end()`, which disconnects the observer, removes listeners, and restores the input row. **Timer scope:** `shell.after(fn, ms)`/`shell.every(fn, ms)` schedule a tracked `setTimeout`/`setInterval` (cancel one early with `shell.cancel(id)`); every tracked timer is force-cleared in `shell.end()`, so no delayed callback can fire into the torn-down game DOM after the player quits. Prefer these over bare `setTimeout`/`setInterval` for any game-lifetime timer (e.g. the racecar HAL-message auto-clears use `shell.after`). Chess does not use the shell (it reads typed moves via `awaitingInput` instead of capturing keys) and lives in its own `chess.js` chunk.

- **Racecar** — lane-based dodge game: 20 Hz logic interval (balance/spawns unchanged) but rendered on a **canvas at 60 fps** with interpolation between ticks — sub-pixel obstacle motion, pixel-scrolling lane dashes, smooth lane-change lerp for the car, and short motion trails on obstacles (the old text-grid renderer juddered cell-to-cell and read as flicker). Start/death screens remain terminal text in the shell's `screen` pre; `showCanvas()` swaps between them. Speed ramps with distance (`BASE_SPEED` → `MAX_SPEED` over ~900 chars); score = distance + 5 per `$` coin collected (coins spawn trailing waves, never in a just-blocked lane — they exist to punish lane-camping). Lane dashes scroll with distance for motion feel; a crash frame shows briefly before the death screen. `safeLane` guarantees at least one clear lane and only shifts into lanes with a clear approach. In godmode: HAL streams obstacle waves in from off-screen and a slow zone applies a 0.55× world-speed multiplier while overlapping the car.
- **Snake** — standard snake; in godmode becomes 4-phase HAL snake (chase blocks → maze → blade spinners → shrinking walls). Phases selected by `halSnakeMode`.
- **Pong** — `PAD_H=4`, ball speed `1.15`, AI tracks 60% of frames. In godmode: HAL gets a second paddle (`rightY2`) and fires interference every 120 ticks (side-switch, speed boost, flip, slow).
- **2048** — standard 4×4. Game over on `!canMove()` (not `boardFull()`). In godmode: HAL steals the 64-tile, locks the 128-tile for 3 moves, rearranges at 256, halves tiles at 512, and "recommends" the worst legal move.
- **Chess** — lives in the lazy `chess.js` chunk (see Architecture); the chess.js engine lib + Stockfish are loaded from CDNs at runtime (the only external code dependencies). Moves typed via `awaitingInput` (bridged). Three tiers: default Skill 5 / 600ms, HAL mode Skill 12 / 1000ms, godmode Skill 20 / 1500ms.
- **Stick Fighter 2000** — fantasy horde-survival game hidden as a desktop icon inside the `gui` XP desktop (desktop only, not in `games`): five hero classes plus a bindable two-player WYRM & RIDER pair, couch + online co-op (WebRTC lockstep), a boss gauntlet (the Nine → Witch-king → stormtroopers → Vader → Sidious → DIO → Ian), a roguelite upgrade tree, boons/banes, daily shared-seed runs, an online leaderboard with watchable replays, and its own in-game trophy case. It lives in the `stickfighter/` part files, assembled into the lazy `stickfighter.js` chunk (see Architecture). **Full game documentation is in `stickfighter/CLAUDE.md`** (auto-loaded when those files are touched) — **read it before changing the game.** The invariants most likely to bite from outside the game: (1) any gameplay-affecting change bumps the sim version in FOUR places (`recHdr.v` / `startWatch` / `NET_SIM_V` / the hal-worker's `REPLAY_VERSION`) and the site + `~/hal-worker` deploy together; (2) online/replay runs persist nothing (`noPersist()`); (3) the site tracks only the `stick-fighter` and `sf-platinum` eggs — in-game trophies never touch `ACHIEVEMENTS` or the OG-image count.

## Achievements
Easter-egg achievements (currently 46) defined in the `ACHIEVEMENTS` array in `app.js` (`{ id, name, desc, hint }`). Found ids persist in localStorage under `ilaird_eggs` (filtered against known ids on load). `unlockAchievement(id)` is idempotent — it saves, updates the 🥚 titlebar badge (`#ach-count` in `index.html`), and shows a toast. `toggleAchievements()` (global — wired to the badge's inline onclick; there is deliberately **no** `achievements` terminal command, badge-click only) lazy-loads the `achui.js` chunk on first click and opens a theme-aware overlay: unlocked entries show name + desc, locked show 🔒 + hint. Escape or clicking the backdrop closes it; while open, a capture-phase key handler shields other listeners. The mobile auto-launch calls `COMMANDS.gui(true)` so it doesn't unlock the `desktop` achievement. On load, `showEggNudge()` points a bobbing arrow at the badge (desktop only); it auto-hides after 60s, and is permanently dismissed (`ilaird_nudge` in localStorage) by its [x], clicking the badge, or opening the overlay — and never shows once any egg is found. When adding a new easter egg, add an `ACHIEVEMENTS` entry and call `unlockAchievement('<id>')` at the moment of discovery. (Stick Fighter is the exception: it keeps its own in-game trophy case — see the Trophy case section in `stickfighter/CLAUDE.md` — and the site tracks only its `stick-fighter` boot egg and the `sf-platinum` full-case egg.)

The overlay UI lives in the lazy `achui.js` chunk (see Architecture) — edit it there. It has two views rendered into the same box: `renderAchList()` (the achievement list, with a `share` button in its header) and `renderShareView()` (a 1200×630 share card rendered to canvas by `buildShareCard()` using the *current* theme colors — red in HAL mode — with copy-to-clipboard (when `ClipboardItem` exists), a download link, native share (when `navigator.canShare` supports files), and a back button). Sharing is overlay-only by design — there is no `share` terminal command. The card shows a HAL eye if `meet-hal` is unlocked.

## Reactive world & the finale
World state derives from the persisted achievement set — `foundEggs.has(id)` — so it survives across visits with no extra storage:
- `meet-hal` → README rule 4 changes ("...well. now you've done it."), `.bash_history` gains apology lines, `ian`'s speech bubble changes.
- `godmode` → `.secrets` gains spooky lines + `key.frag[4/4]`, `hal9000.core` appears in `ls`/`cat` (contains `key.frag[1/4]`; its hex spells "daisy daisy give me your answer do"), `neofetch` gains a defunct `hal9000d` process, `hal` refuses (pre-existing).
- `bad-time` → `a_letter_from_sans.txt` appears (contains `key.frag[3/4]`, points to the core dump).
- `neofetch` always shows `key.frag[2/4]` (a deliberate teaser for everyone).

**Finale**: when `foundEggs.size === ACHIEVEMENTS.length`, `armFinale()` polls until the terminal is idle (no game/mode/awaitingInput/overlay), then `runFinale()`: red flicker → `hal-restored` amber theme → HAL reconciliation lines (TTS/typewriter only for now — to upgrade, generate clips and pass clipKeys to the `halTypeLine` calls) → Daisy softly at 0.3 volume → credits roll → back to normal theme → drops `the_last_egg.txt`. Sets `ilaird_ending` in localStorage (`endingSeen`); a load-time check re-arms if the page closed mid-unlock. `credits` (in `COMMANDS`, plays the roll) and the `decrypt` prefix handler are gated on `endingSeen`.

**The decrypt puzzle** (two stages): `the_last_egg.txt` holds two XOR-encrypted hex segments. Segment 1 (`EGG_CIPHER`): key `DAISY2001HAL9000` from the four on-site fragments → decrypts to "Send Ian an email with the title stardust". Segment 2 (`EGG2_CIPHER`): key `DAISY2001HAL9000DAVE` — the fifth fragment (`key.frag[5/5] = "DAVE"`) is **not on the site**; it's delivered by the Proton Mail Sieve auto-reply that fires on subject "stardust" (configured in Proton, not in this repo — if the Sieve filter is ever removed, segment 2 becomes unsolvable). Decrypts to "CHRIST IS KING - Spread the word". `decrypt <key>` normalizes input (strips separators, uppercases) and validates against `EGG_KEY_HASH`/`EGG2_KEY_HASH` (djb2, stage 2 checked first); plaintexts are not stored in source. At 26/26 the overlay header shows "— complete" and the share card footer goes gold ("daisy, daisy").
