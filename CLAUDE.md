# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview
Single-page terminal-style portfolio site hosted on GitHub Pages. No build system, no framework, no dependencies — hand-written files: `index.html` (markup), `style.css`, `app.js` (the core terminal), the pure `lib/` helpers, and seven lazy-loaded chunks fetched on first use (see Architecture): `stickfighter.js` (the Stick Fighter 2000 game), `games.js` (the four shell games — racecar/snake/pong/2048), `sans.js` (the sans easter egg), `chess.js` (the chess game), `halllm.js` (the experimental LLM HAL), `desktop.js` (the XP desktop behind `gui`), and `achui.js` (the achievements overlay + share card). Pre-recorded HAL 9000 audio clips live in `assets/audio/` (~135 mp3 files generated via ElevenLabs), alongside music tracks and `sans_voice.mp3`. To regenerate clips, run `./generate_hal_audio.sh` (requires ElevenLabs API key set in the script).

## Deployment
Push to `main` branch → auto-deploys via GitHub Pages. The `.nojekyll` file disables Jekyll processing.

**Service worker (`sw.js`):** GitHub Pages serves everything with `Cache-Control: max-age=600` (not configurable), so `sw.js` provides repeat-visit caching: **cache-first** for `assets/audio/*` (a played HAL clip or music track never re-downloads; audio is fetched by URL so Range requests still cache the full file) and **stale-while-revalidate** for every other same-origin GET (the JS bundle + lazy chunks, HTML, CSS — a returning visitor gets the previous build once after a deploy, the new one on the next load; safe because the chunk entry names + api bridge keys are stable across builds). Cross-origin (CDNs, Turnstile, the hal-worker API) and non-GET requests are never intercepted. Registered at the bottom of `app.js` after `load`, **skipped on localhost/http** (dev stays cache-free). It ships unobfuscated (copied through in `build.js`'s `STATIC` list; `verify-build` asserts it's present). **Bump `VERSION` in `sw.js` to flush all caches on a breaking deploy.** `test/sw.test.js` runs the real file in a stubbed SW environment and pins the routing contract.

## Obfuscated build (optional, for hiding easter-egg secrets)
The site is normally served as the clean hand-written source. `npm run build` (`scripts/build.js`) produces a `dist/` whose JS is obfuscated gibberish — for deploying a build whose secrets (the hunt logic, decrypt puzzle, HAL, finale) aren't trivially readable or paste-into-an-LLM-able. **It's opt-in: the clean source stays the source of truth, `npm run serve` serves it directly, and all tests run against it, not the build.** `dist/` is gitignored. The deploy topology (private source → push `dist` to the public Pages repo) is intentionally left to the operator — `build.js` only produces the artifact.
- **Topology:** `dist/app.js` = `lib/*.js` + `app.js` concatenated, wrapped in ONE IIFE, obfuscated **heavily** (control-flow flattening, dead code, string-array). lib must bundle with app.js (it reads `_djb2`/`_xorDecode`/`_alignTimings`/`_halNorm`/`makeRng` plus the `lib/shell.js` parsers). The seven lazy chunks — `dist/stickfighter.js`, `dist/games.js`, `dist/sans.js`, `dist/chess.js`, `dist/halllm.js`, `dist/desktop.js`, `dist/achui.js` — are each wrapped in their own IIFE and obfuscated **lightly** (identifier mangling + plain string relocation, **no control-flow flattening** — the game chunks run frame loops and the others are small UI shells; one config keeps them uniform). They're separate chunks because each reaches app.js only through its `api` bridge. `dist/index.html` collapses the six lib+app `<script>` tags to one `app.js`.
- **Why the IIFE wrap:** obfuscators leave true globals alone; wrapping makes the top-level names function-scoped so they get renamed. This is why app.js exports its 4 inline-handler functions to `window` and each chunk exports its entry (`openStickFighter` / `initGames` / `initSansMode` / `initChess` / `initHalLLM` / `initDesktop` / `initAchUI`) via an explicit `window.<name> =` line (see Architecture) — those survive the wrap.
- **Config invariants (in `build.js`):** `renameProperties`/`transformObjectKeys` **OFF** (worker JSON fields, DOM props, the `api.*` keys, and `window.<fn>` exports are literal property names); the chunk entries `openStickFighter`/`initGames`/`initSansMode`/`initChess`/`initHalLLM`/`initDesktop`/`initAchUI` reserved on both sides (each lazy-load handshake crosses its chunk boundary by that name); no source maps.
- **`npm run verify-build`** (`scripts/verify-build.js`, run after build): boots the real obfuscated bundle in jsdom (asserts the terminal comes up + the public API survived — catches obfuscation breakage that "it parses" misses), drives the obfuscated game chunk headlessly with a fixed seed and times it against the clean source (asserts the light config kept overhead negligible — empirically the game runs ≈ the same or slightly faster, since `simplify`/`compact` offset the near-zero mangling cost), then executes `dist/games.js`, `dist/sans.js`, `dist/chess.js`, `dist/halllm.js`, `dist/desktop.js`, and `dist/achui.js` and asserts each still exports its `window.<entry>` and returns the handler keys app.js calls.

## Testing
`npm test` runs `node --test` over `test/`. CI (`.github/workflows/ci.yml`) runs `npm run check` = lint (ESLint) + lint:html (html-validate) + format:check (Prettier) + test. Two kinds of tests:
- **Pure-helper unit tests** (`test/codec.test.js`, `timing.test.js`, `text.test.js`, `rng.test.js`, `shell.test.js`) cover the dual-mode `lib/*.js` helpers (they `module.exports` for Node and define browser globals for the page). Logic worth testing is best extracted into a `lib/` helper so it can be unit-tested without a DOM. `lib/rng.js` (seeded mulberry32 PRNG + `hashSeed`) is the determinism foundation for Stick Fighter — `rng.test.js` pins the algorithm so saved seeds/replays can't silently break. `lib/shell.js` holds the terminal's pure shell parsers (tokenizing, globs, pipe filters grep/head/tail/wc, history `!`-expansion, `$VAR` expansion, path resolution, the session-overlay `mergeNode`); the state-reading ones take `cwd`/`cmdHistory`/home as parameters, and app.js keeps thin same-named adapters (`fsResolve`/`fsDisplay`) or passes the state at call sites.
- **Boot smoke test** (`test/boot.test.js`, uses `jsdom`) loads the real `index.html` + the real `lib/*.js` → `app.js` script chain into a jsdom DOM, runs `boot()`, and asserts the terminal comes up, the inline-HTML global handlers exist, `help` dispatches, output reaches `#a11y-live`, and the global error boundary recovers a wedged terminal (it dispatches a synthetic `error` event and checks the prompt is restored). This catches the load-time `ReferenceError` class that linting can't — important because `app.js` is one no-IIFE classic script where every top-level name shares one global scope. It shims the few browser APIs `app.js` uses unguarded at load (`Audio`, `fetch`, canvas `getContext`); `matchMedia`/`AudioContext`/`speechSynthesis` are left undefined on purpose to exercise the real feature-guards. Each test calls `dom.window.close()` (via `t.after`) to stop jsdom timers — without it the `showEggNudge` 60s timeout keeps the process alive.
- **Stick Fighter determinism** (`test/stickfighter-determinism.test.js`, uses `jsdom`) drives the real game headlessly (recording-canvas context that folds every draw op into a rolling hash **plus per-tick chunk hashes split on each full-screen clearRect**, manual `requestAnimationFrame` pump with configurable frame cadence, fixed seed via stubbing the `init()` entropy draw) and pins four properties: a run is reproducible from its seed (same seed → identical draw stream); a different seed diverges (proving the stream reflects RNG-driven gameplay); **60 Hz and 120 Hz pumps over the same wall-clock span produce the identical tick stream** (chunk-by-chunk equal, totals within the one boundary tick — guards the fixed-timestep driver); and **`reduceMotion` does not change how many `rnd()` draws the sim makes** (via an instrumented `makeRng` in the stub bridge — guards settings-independent RNG consumption). It builds a stub `api` bridge to launch the game (see Architecture).
- **Chunk isolation** (`test/stickfighter-isolation.test.js`, `games-isolation.test.js`, `sans-isolation.test.js`, `chess-isolation.test.js`, `halllm-isolation.test.js`, `desktop-isolation.test.js`, `achui-isolation.test.js` — pure static lint, no DOM) enforces that each lazy chunk references no app.js/lib global by free name (everything via its `api` bridge), so each stays independently bundle/obfuscate-able. Lints the file alone with `no-undef` + browser globals only; any flagged name must be routed through the matching bridge (`sfBridge()` / `gamesBridge()` / `sansBridge()` / `chessBridge()` / `halLLMBridge()` / `desktopBridge()` / `achBridge()`).
- **Achievement integrity** (`test/achievements.test.js`, pure file parsing — no DOM) guards the easter-egg count from silent drift: ids are unique, the count baked into `generate_og_image.sh` ("N easter eggs") matches `ACHIEVEMENTS.length`, and every literal `unlockAchievement('id')` call site (across `app.js`, the lazy chunks, and `index.html`) references a defined id. Dynamic calls (`unlockAchievement(data.ach)` etc.) are excluded since they resolve at runtime. **When you add/remove an achievement, re-run `./generate_og_image.sh`** or this test fails.

## Architecture
`index.html` is bare markup (~100 lines); the core terminal lives in `app.js` (~3,700 lines), loaded as a classic script at the end of `<body>`. It must stay a classic script (not a module): the inline `onclick` handlers in `index.html` (`toggleSound()`, `focusCmd()`) rely on its top-level functions being globals, and the element lookups at the top of the file rely on the DOM existing. **app.js is NOT wrapped in an IIFE** — its top-level `const`/`let`/`function` declarations sit in the shared global lexical scope, which is what lets the lazily-loaded chunks (separate classic scripts) find their `window.<entry>` handshake. Seven feature areas are **not** in app.js — each lives in its own lazily-fetched chunk behind an explicit `api` bridge (see the sections below): `stickfighter.js` (Stick Fighter 2000), `games.js` (the four shell games), `sans.js` (the sans easter egg), `chess.js` (chess), `halllm.js` (the experimental LLM HAL), `desktop.js` (the `gui` XP desktop, which also hosts the Stick Fighter loader), and `achui.js` (the achievements overlay + share card). The bridge pattern is identical across all of them: app.js builds an `api` object (`gamesBridge()` / `sansBridge()` / `chessBridge()` / `halLLMBridge()` / `desktopBridge()` / `achBridge()` — `sfBridge()` lives inside desktop.js and re-exposes desktopBridge values) whose keys are the stable contract — stable functions/elements are plain keys the chunk destructures, runtime-varying flags are getters (and setters where the chunk writes back, e.g. `activeMusic`, `sansBattleActive`, `awaitingInput`); the chunk references nothing from app.js by free global name (statically enforced per chunk by the isolation tests). The pure shell parsers (tokenizing, globs, pipe filters, history/`$VAR` expansion, path resolution, `mergeNode`) live in `lib/shell.js` — see Testing. Key sections:

**Lazy-loaded Stick Fighter (`stickfighter.js`):** the ~4,500-line Stick Fighter 2000 game was extracted out of `app.js` into its own file so the ~280 KB of game code is **not** in the initial page load. It's fetched on demand the first time the desktop icon is opened: `launchStickFighter()` (inside the `desktop.js` chunk's `launchXP` closure) injects `<script src="stickfighter.js">` once (guarded by a `sfLoading` promise + a `typeof window.openStickFighter` check), then calls the global `window.openStickFighter(xp, api)` it defines — a chunk-to-chunk handshake, which is why both entries are reserved names. **Dependency bridge (obfuscation-readiness):** the game takes every app.js/lib dependency through an explicit `api` object built by `sfBridge()` in desktop.js (which re-exposes values from app.js's `desktopBridge()`) — `unlockAchievement`, `_chirp`, `makeRng`, `HAL_WORKER_URL`, plus live `soundEnabled`/`reduceMotion` getters and an `activeMusic` getter/setter (the game writes it). Inside `openStickFighter` the stable ones are destructured (`const { unlockAchievement, _chirp, makeRng, HAL_WORKER_URL } = api;`, so call sites are unchanged) and the runtime-varying ones are read/written as `api.soundEnabled` / `api.reduceMotion` / `api.activeMusic`. It references **nothing** from app.js by free global name, so it can be bundled & obfuscated as an independent lazy chunk without cross-file name-mangling breaking — the only contract is the `openStickFighter` name + the `api` key names (both must go on the obfuscator's reserved-names list). `test/stickfighter-isolation.test.js` statically enforces this (lints the file in isolation with `no-undef`, asserts zero free app.js/lib refs); add a key to `sfBridge()` (and, if app.js must supply it, to `desktopBridge()`) if it ever fails. The desktop is passed in as the `xp` parameter; the running game parks its teardown on `xp._sfCleanup` so the desktop's `shutdown()` (ESC) can stop it. When editing the game, edit `stickfighter.js`, not `app.js`. Keep it a classic script and keep its original 8-space indentation (it has multi-line template literals; blanket de-indenting would corrupt them).

**Lazy-loaded shell games (`games.js`):** `createGameShell` and the four shell-game commands (racecar / snake / pong / 2048, ~1,400 lines) live in `games.js`, fetched on demand the first time one is launched. The `COMMANDS` entries in app.js are one-line stubs calling `launchGame(name)`, which injects `<script src="games.js">` once (guarded by a `gamesLoading` promise + a `typeof initGames` check), calls the global `initGames(api)` it defines (with `gamesBridge()`: `appendNode`/`blank`/`scroll`/`halSpeak`/`halD`/`unlockAchievement`/`_chirp` + the `inputRow`/`cmd` elements, plus live `godmodeUnlocked`/`playerName` getters), caches the returned `{racecar, snake, pong, '2048'}` handlers, and dispatches. A load failure prints an error line and resets `gamesLoading` so retyping the command retries. `chess` is NOT in this chunk (it doesn't use the shell; it stays in app.js). When editing these games, edit `games.js`, not `app.js` — and keep its original indentation (multi-line string screens).

**Lazy-loaded sans mode (`sans.js`):** the whole Undertale easter egg — `activateSansMode`, the out-of-battle command set, and the ~700-line persistent battle — lives in `sans.js`, fetched on demand when the mode is first summoned: the `sans` command **prefetches it during HAL's long speech** (so it's loaded by CONFIRM time; `showSans()` then goes through `loadSansMode().then(...)` with `sansLoadFailed()` as the error path), and `sss` loads it directly. `initSansMode(api)` returns `{ activate, command, battleCommand }`; app.js's `sansMode` dispatch block routes typed input to `sansHandlers.command(token, raw)` (or `.battleCommand(token)` during a battle) — safe because `sansMode` can only become true after the chunk's `activate()` ran. **The mode flags stay owned by app.js**: `sansMode` and `sansBattleActive` are app.js globals (read by the dispatcher, `getPromptHTML`, the finale idle-poll, `resumeModeAudio`, and the Konami handler); the chunk reads/writes them through `sansBridge()` accessors, and writes `activeMusic` the same way so the sound toggle reaches the battle music. `sansChirp`/`chirpTypeLine`/`showConfirmOverlay` stay in app.js (the `sans`-command speech/handoff and the Konami dirty-hacker response use them app.js-side) and are passed through the bridge; `sansBattle`/`sansDeaths` moved into the chunk. When editing sans content, edit `sans.js`, not `app.js` — and keep its original indentation.

**Lazy-loaded chess (`chess.js`):** the chess game (~230 lines) lives in `chess.js`, fetched on demand the first time `chess` (or HAL mode's `play chess`) is run — the `COMMANDS.chess` entry is a stub calling `launchChess()`. `initChess(api)` returns `{ chess }`; `chessBridge()` carries the output helpers + `inputRow`/`cmd`, live `halMode`/`godmodeUnlocked`/`soundEnabled`/`playerName` getters (difficulty tier and quips are chosen per launch), and **`awaitingInput`/`silentInput`/`activeMusic` accessors the chunk writes back through** — typed moves flow from app.js's Enter handler into the chunk via the `awaitingInput` callback, so that flag must stay app.js-owned. The chess.js/Stockfish CDN loading is unchanged inside the chunk; the CDN engine global is deliberately referenced as `window.Chess` (a bare `Chess` would fail the isolation lint). When editing chess, edit `chess.js`, not `app.js`.

**Lazy-loaded LLM HAL (`halllm.js`):** the whole experimental "escape the terminal" mode — the CONFIRM overlay, Turnstile loading + bot gate, session/turn networking, the meters HUD, and the win/lose/broken endings (~400 lines) — lives in `halllm.js`, fetched on demand when a player picks **[2]** at the `hal` prompt (the two-HAL menu **prefetches it** while the player reads, so it's usually loaded by choice time; `halLLMLoadFailed()` is the error path and resets the loader for retry). `initHalLLM(api)` returns `{ showInfoPage, handleInput }`; app.js's dispatcher routes typed input to `halLLMHandlers.handleInput(raw)` — safe because `halLLM` can only become true after the chunk's `startHalLLM` ran. **The mode flags stay owned by app.js**: `halMode`, `halLLM`, and `halLLMBusy` are app.js globals (the dispatcher reads them; `restoreNormal` resets them); the chunk writes them through `halLLMBridge()` accessors. The per-session state object (`halLLMState`) moved into the chunk. `halAskNameAndSound` stays in app.js (shared with the classic HAL) and is passed through the bridge; `halEyePre` and the Turnstile loader moved in (the Turnstile global is deliberately read as `window.turnstile`). `daisy`/`clear` cross the bridge as wrapper functions around the `COMMANDS` entries. When editing the LLM HAL, edit `halllm.js`, not `app.js`.

**Lazy-loaded XP desktop (`desktop.js`):** the fake Windows-XP desktop behind `gui` — bliss wallpaper, icons, taskbar, start menu, and the Stick Fighter lazy-loader (~250 lines) — lives in `desktop.js`, fetched on demand the first time `gui` runs; `COMMANDS.gui` is a stub that unlocks the `desktop` egg (unless auto-launched) and calls `launchDesktop()`. The mobile auto-launch (`COMMANDS.gui(true)`) goes through the same stub. `initDesktop(api)` returns `{ open }`; `desktopBridge()` carries `cmd`/`openUrl`/`unlockAchievement` for the desktop itself plus everything `sfBridge()` (now inside this chunk) re-exposes to Stick Fighter: `_chirp`, `makeRng`, `HAL_WORKER_URL`, and live `soundEnabled`/`reduceMotion`/`activeMusic` accessors. When editing the desktop, edit `desktop.js`, not `app.js`.

**Lazy-loaded achievements overlay (`achui.js`):** the easter-egg panel behind the titlebar 🥚 badge — the unlocked/locked list, the share view, and the 1200×630 share-card canvas (~260 lines) — lives in `achui.js`, fetched on demand the first time the badge is clicked; `toggleAchievements()` in app.js is the loader stub (it stays app.js-side and window-exported because the badge's inline `onclick` calls it by name, and it still dismisses the egg nudge before loading). `initAchUI(api)` returns `{ toggle }`; `achBridge()` carries `ACHIEVEMENTS`, the live `foundEggs` set, `cmd`, and an **`achOverlayEl` accessor — that element handle stays owned by app.js** because `tryStartFinale` polls it to avoid interrupting an open overlay. `unlockAchievement`/`syncEggBadge`/`eggToast`/`showEggNudge` stay in app.js (they're called from everywhere, including the other chunks' bridges). When editing the overlay or share card, edit `achui.js`, not `app.js`.

- **CSS variables** (`:root` in `style.css`) — color scheme. HAL mode and sans mode overwrite these at runtime via `document.documentElement.style.setProperty`; `restoreNormal()` removes the overrides. The godmode rainbow does NOT touch the variables — it's a compositor-animated `filter: hue-rotate` sweep (`.godmode-rainbow` on `.window` in `style.css`, added by `startRainbow()`), so mode themes keep working underneath it and it costs no per-frame style recalc. Because `filter` makes `.window` the containing block for `position: fixed` descendants, full-screen overlays must keep being appended to `document.body` (the existing pattern), never inside `.window`. Each `THEMES` entry also carries a `title` (document title) and `icon` (data-URI SVG favicon) — `applyTheme()` swaps the browser tab's appearance along with the colors (red HAL eye favicon in HAL mode), and is called once at load to set the defaults.
- **Reduced motion** — a live `reduceMotion` flag (top of `app.js`, from `matchMedia('(prefers-reduced-motion: reduce)')`, re-read on `change`) gates the photosensitive/vestibular effects: the godmode rainbow becomes a single static palette (`applyGodmodeTint()` instead of the cycling hue-rotate animation; the CSS side also halts `.godmode-rainbow` under the media query), `redFlicker()` (finale strobe) no-ops, Stick Fighter screen-shake keeps its countdown but skips the canvas translate, and the in-game telegraph flashes (enemy `aim`/`wind` colors, the red `!` spawn warnings, trooper pre-fire flash, Excalibur-expiry blink) render steady instead of blinking. CSS side: `@media (prefers-reduced-motion: reduce)` in `style.css` disables the looping `egg-nudge`/`.gold-pop` glow animations.
- **Global error boundary** — `window` `error`/`unhandledrejection` listeners (near the top of `app.js`, after `openUrl`) call `handleFatal()`: it logs, re-shows the input row, and prints one in-character recovery line so an uncaught throw inside a game loop or async chain can't leave a dead, inputless page. It's on the bubbling path (no capture) so it catches script errors only — a 404'd audio clip or a down chess CDN won't read as a "fault". Debounced (`_faultActive`, 1.5s) so a loop that throws every frame can't spam recovery lines. All audio `play()` rejections are `.catch()`-ed at their call sites, so a rejection that reaches the boundary is a genuine bug.
- **Screen-reader announcer** — terminal output (`#out`) is a stream of typewriter text and full-screen game canvases, so `#out` itself is **not** an aria-live region (it would announce every typewriter character and every game frame). Instead `index.html` has a separate visually-hidden polite live region `#a11y-live` (`role="log"`, `aria-live="polite"`, inline-clipped like the SEO `sr-only` block). `announce(str)` (in `app.js`, next to `line()`) mirrors each **completed** line into it, pruned to a ~30-node window. `line()`/`text()` announce automatically; the typewriters (`halTypeLine`, `chirpTypeLine`, `playHalVoiceLine`, the `daisy`/sans-confirm `playClipTyped` calls) call `announce()` once with the full line up front so assistive tech reads it without per-character stutter. New output paths that build a line by mutating an element (rather than via `line()`/`text()`) should `announce()` the final text themselves.
- **`COMMANDS` object** — each key is a command name, value is a function. Multi-word commands use quoted string keys e.g. `'power off'`.
- **Command dispatch** — `submitCommand(raw)` checks the `awaitingInput` callback first, then the `halMode` block, then the `sansMode` block, then `COMMANDS[token]`. Special prefix checks: `cat <file>`, `sss` (sans shortcut), `help --all`. Called by the Enter key handler and by **click-to-run**: a delegated click listener on `#out` executes `.blue` spans whose text is a runnable token (`clickRunnable()` — per-mode allowlists; ignores clicks while `awaitingInput` is set or the input row is hidden by a game). Blue spans get pointer/underline affordance via CSS, so command names printed in output should use `class="blue"` only when actually runnable. Unknown commands in normal mode occasionally (25%, suppressed post-godmode) get a HAL nudge line pointing at `hal`.
- **`halMode` flag** — when true, the key handler refuses most commands and routes unknown input to `halChat()`.
- **`sansMode` flag** — when true, input routes to the sans command set (`fight`, `check`, `act`, `joke`, `mercy`, etc.) or `sansUnknown()`. During a battle (`sansBattleActive`), typed input goes to `sansBattleCommand()` instead.
- **`awaitingInput`** — a callback variable set when multi-step terminal input is needed (e.g. the `hal` setup flow asking for name then sound preference, or chess move entry). The key handler calls it and returns early, bypassing all other logic. `silentInput` suppresses the prompt echo while it's set (used by chess).
- **`playerName`** — set during `hal` setup (default `'Dave'`). Used everywhere HAL addresses the user. `halD(s)` replaces `\bDave\b` with `playerName` for display text.
- **`godmodeUnlocked`** — set by the Konami code (in HAL mode or normal mode). Enables HAL hard-mode variants in the games and the rainbow color cycle, plus the `override` command.
- **`soundEnabled`** — off by default. Toggled via the titlebar toggle, `settings` / `sound on` / `sound off`, or the `hal` setup flow. Turning sound off calls `stopAllAudio()`: cancels TTS, pauses the current HAL clip **and manually fires its `onended` handler** (chained sequences and `playClipTyped` await `onended` — without this, in-flight typewriter lines would hang forever), pauses the sans menu music, and pauses `activeMusic`. `activeMusic` tracks closure-local music (sans battle, chess) so the toggle can reach it; those closures null it on their own cleanup. Turning sound on calls `resumeModeAudio()` (resumes `activeMusic`, else sans menu music if in sans mode). New looping/long music must set `activeMusic` when starting and clear it on cleanup.

## HAL audio system
- **`halPlayKey(key)`** — plays `assets/audio/${key}.mp3`. Returns a `Promise` that resolves on `onended`/`onerror`, so sequential HAL lines can be chained with `.then()` rather than fixed `setTimeout` delays. When `soundEnabled` is false, returns `Promise.resolve()` immediately.
- **`halSpeak(text)`** — normalizes text via `_halNorm()` (strips `HAL:` prefix, strips player name from surrounding punctuation, expands em-dashes), looks up the result in `HAL_CLIPS`, and calls `halPlayKey`. Falls back to browser TTS for any text not in the table.
- **`HAL_CLIPS`** — lookup table mapping normalized text → clip filename. ~100 entries covering all fixed HAL lines across all games and interactions.
- **`halTypeLine(text, clipKey)`** — typewriter effect synced to ElevenLabs per-character timing data (`assets/audio/hal_timing.json`, loaded into `HAL_TIMING`). `_alignTimings()` LCS-aligns clip characters to display text so injected player names don't break sync. Falls back to a `currentTime/duration` loop if timing isn't loaded, or a fixed-rate typewriter when sound is off.
- **Sans chirps** — `chirpTypeLine(text, chirpFn, msPerChar)` types text with a per-character sound; `sansChirp` clones `sans_voice.mp3`, `halChirp` is a WebAudio sine blip.
- **When adding a new HAL line:** if it's a fixed string, add an entry to `HAL_CLIPS` and generate the clip with `generate_hal_audio.sh`. If it contains player name, the normalized key should have the name stripped (handled automatically by `_halNorm`). Call `halPlayKey(key)` directly at the call site rather than `halSpeak(text)` when the key is known.
- **Sequential lines** (SSH, godmode Konami sequence): chain via `.then()` on `halPlayKey`, not `setTimeout`.

## LLM HAL — "escape the terminal" (experimental, opt-in)
A second, optional HAL: a live language model role-plays HAL trying to stop you from leaving. **The scripted HAL above is untouched** — this only runs when `halLLM` is true. The whole mode lives in the lazy `halllm.js` chunk (see Architecture) — edit it there; app.js keeps only the flags, bridge, and loader. Flow: `hal` → choose **[2]** (prefetched at the menu; loaded via `loadHalLLM()`) → `showHalLLMInfoPage()` → `showHalLLMConfirmOverlay()` (a full-screen red CONFIRM gate stating it's LLM-based, the escape-game rules, and a misuse warning; type CONFIRM to proceed / Escape to back out) → `askHalLLMName()` (name + optional voice) → `startHalLLM()` (sets `halMode` **and** `halLLM`, red theme, cold open, prints the meter HUD). The website is the renderer; a **separate backend service is the brain** (AWS Lambda + API Gateway + DynamoDB, in `~/hal-worker`; base URL `HAL_WORKER_BASE`, overridable via `localStorage.ilaird_hal_worker`).
- **Bot gate (Cloudflare Turnstile + session handshake):** `startHalLLM()` first calls `halLLMOpenSession()` → `getTurnstileToken()` runs an invisible Turnstile challenge (script in `index.html`, `TURNSTILE_SITE_KEY`; widget renders inline so a rare interactive challenge is completable) → POSTs `{tsToken}` to `POST {base}/session`, which returns a short-lived signed `sessionToken` stored in `halLLMState.sessionToken`. `halLLMBusy` stays true during the handshake; failure (no token / unreachable) → `halLLMEndBroken()`. Subsequent turns carry the `sessionToken`; no per-turn challenge. The backend (not the browser) holds the Anthropic key and enforces per-IP rate limits + a daily cap.
- **Game:** two meters — `escape` (0→100) and `control` (0→100). Each turn `handleHalLLMInput()` POSTs `{playerName, message, history (last ~12), state:{escape,control,turn}, sessionToken, voice}` (`voice` = `soundEnabled`) to `POST {base}/turn` and expects JSON `{reply, escape, control, event?, outcome:"ongoing"|"escaped"|"caught", audio?, alignment?}`, then prints `event` (dim), redraws the HUD (`renderHalMeters()` — per-line `▰▱` bars). `escaped`/escape≥100 → `halLLMWin()` (`outsmarted-hal` egg). `caught`/control≥100 → `halLLMLose()` (`disconnected-by-hal` egg). Both end with `restoreNormal()`.
- **Voice (optional, sound-gated):** the client sends `voice: soundEnabled`, so the backend only synthesizes when the player has sound on. When the backend returns `audio` (base64 mp3), `playHalVoiceLine()` plays it and reveals "HAL: …" synced to `alignment` (ElevenLabs per-character timings, via the same `_alignTimings` LCS used for scripted clips), tracked through `halAudioEl` so the sound toggle's `stopAllAudio()` can stop it. No audio → `halTypeLine()` types at a fixed rate (+ browser TTS if sound on). Backend voice = ElevenLabs **Flash** (`eleven_flash_v2_5`) in the scripted-HAL voice (`ki9mNgaTTZJesOJj7cZB`) via the `/with-timestamps` endpoint, gated by a **separate low daily cap** (`VOICE_DAILY_LIMIT`, default 20, its own DynamoDB counter); over-cap or any TTS failure just omits `audio`. Disabled entirely if `ELEVENLABS_API_KEY` is unset. The mode's **static lines** (cold open `hal_llm_open`, and `hal_llm_win`/`hal_llm_lose`/`hal_llm_broken`) are pre-recorded clips like the scripted HAL — generated by `generate_hal_audio.sh` (canonical name "Dave", re-synced per player via `_alignTimings`) and passed to `halTypeLine(text, clipKey)`; only the live per-turn replies use the backend TTS path.
- **In LLM mode the dispatch is simple** (`if (halLLM)` branch at the top of `submitCommand`'s `halMode` block): only `daisy` (bail) and `clear` are commands; **everything else routes to the model** — typing `open pod bay doors`, `sudo disconnect hal`, etc. *is* the gameplay. `halLLMBusy` locks input during a request; `halLLMShowThinking()` shows a "HAL is considering you…" indicator (static under `prefers-reduced-motion`).
- **No offline mode by design:** if the worker is unconfigured, unreachable, times out (15s), or returns anything malformed (`halLLMRequest()` validates shape), the session ends in character via `halLLMEndBroken()`.

## Games
The four shell games (racecar / snake / pong / 2048) are self-contained closures in the lazy `games.js` chunk (see Architecture — their `COMMANDS` entries are `launchGame()` stubs), built on **`createGameShell({ hint, lineHeight, halMsg, onKeyDown, onKeyUp })`** (also in `games.js`) — it creates the wrap/screen/hint DOM, hides the input row, and registers key listeners; the optional `halMsg: 'top' | 'bottom'` adds a HAL message line auto-spoken via MutationObserver. It returns `{ wrap, screen, halMsgEl, end, after, every, cancel }`; the game's own `end()` does game-specific teardown (intervals, timers) then calls `shell.end()`, which disconnects the observer, removes listeners, and restores the input row. **Timer scope:** `shell.after(fn, ms)`/`shell.every(fn, ms)` schedule a tracked `setTimeout`/`setInterval` (cancel one early with `shell.cancel(id)`); every tracked timer is force-cleared in `shell.end()`, so no delayed callback can fire into the torn-down game DOM after the player quits. Prefer these over bare `setTimeout`/`setInterval` for any game-lifetime timer (e.g. the racecar HAL-message auto-clears use `shell.after`). Chess does not use the shell (it reads typed moves via `awaitingInput` instead of capturing keys) and lives in its own `chess.js` chunk.

- **Racecar** — lane-based dodge game: 20 Hz logic interval (balance/spawns unchanged) but rendered on a **canvas at 60 fps** with interpolation between ticks — sub-pixel obstacle motion, pixel-scrolling lane dashes, smooth lane-change lerp for the car, and short motion trails on obstacles (the old text-grid renderer juddered cell-to-cell and read as flicker). Start/death screens remain terminal text in the shell's `screen` pre; `showCanvas()` swaps between them. Speed ramps with distance (`BASE_SPEED` → `MAX_SPEED` over ~900 chars); score = distance + 5 per `$` coin collected (coins spawn trailing waves, never in a just-blocked lane — they exist to punish lane-camping). Lane dashes scroll with distance for motion feel; a crash frame shows briefly before the death screen. `safeLane` guarantees at least one clear lane and only shifts into lanes with a clear approach. In godmode: HAL streams obstacle waves in from off-screen and a slow zone applies a 0.55× world-speed multiplier while overlapping the car.
- **Snake** — standard snake; in godmode becomes 4-phase HAL snake (chase blocks → maze → blade spinners → shrinking walls). Phases selected by `halSnakeMode`.
- **Pong** — `PAD_H=4`, ball speed `1.15`, AI tracks 60% of frames. In godmode: HAL gets a second paddle (`rightY2`) and fires interference every 120 ticks (side-switch, speed boost, flip, slow).
- **2048** — standard 4×4. Game over on `!canMove()` (not `boardFull()`). In godmode: HAL steals the 64-tile, locks the 128-tile for 3 moves, rearranges at 256, halves tiles at 512, and "recommends" the worst legal move.

Qualification is judged against the board matching the run type; if the run cracks its top 10 it prompts for a name (`lbState='enter'`, typed via the `onKey` capture that swallows letters/digits so they don't fire cheats or the R-restart), then `lbSubmit()` POSTs `{name, score, wave}` — **plus `day` on a daily run** — to `/score` and `drawDeathScreen()` renders **both top-10 boards side by side** (ALL TIME + ☀ TODAY; single centred column when there's no daily board), highlighting the player's row on the board they submitted to. The whole flow is **best-effort and degrades silently** — worker unreachable or score 0 → `lbState='off'`, the original local-best screen. **Run proof (minimal, O(1) — proof of TIME + PLAUSIBILITY, not proof of play):** when a run starts, `beginRunProof()` fire-and-forgets `POST /run-start`, which mints an HMAC-signed **run token** (`{typ:'run', rid, iat}`, same secret as the LLM-HAL session tokens) pinning the run's true start time; `endRun()` freezes `lbTicks`/`lbKills`, and `lbSubmit()` sends `{token, ticks, kills}` with the score. The worker's `verifyRun()` rejects (400) any submit whose token is missing/forged/expired/**already used** (single-use via a TTL'd DynamoDB counter on `rid`), whose tick count outruns wall-clock time since `iat` (you cannot claim a 20-minute run 20 seconds after starting; 66 ticks/s + slack), or whose stats break the game's own rules — minimum run length, wave pacing (≥~250 ticks/wave), kill budget vs. wave (spawn-pipeline bound), score budget vs. kills+ticks (≤720/kill + <20000 flat boss bonuses + ≤1/tick passive; constants deliberately generous — they reject the absurd, not the marginal). `REQUIRE_RUN_PROOF=0` is the worker-side kill switch; a rejected/tokenless submit degrades to `lbState='view'`. Anything the client computes is forgeable, so **full proof of play remains the documented upgrade path**: re-simulate the recorded per-tick inputs server-side over the deterministic sim — the recording now EXISTS (see replays below), only the server-side re-run doesn't. **Replays / "watch a legend":** every live run is recorded — `recPush` appends `[tick, code, arg?]` events (codes: 0 held-direction mask change · 1–4 P1/P2 dash/attack at pend consumption · 5 summon · 6 choke-mash · 7 shop buy (by upgrade id) · 8 shop continue · 9 boss-intro advance · 10 the Ian choice · 11 spell-page cycle (arg = hero index) · 12 boon pick (arg = boon id)), and `recHdr` (built in `init()`) captures every piece of persistent state the sim reads at start: `{v, seed, c1, c2, coop, hd (hard mode), up0 (owned upgrade ids), tk0 (token balance), mw0 (lifetime maxwave)}`. **`v` is the SIM-BALANCE version (currently 3): bump it in all three places — `recHdr`, `startWatch`'s check, and the worker's `REPLAY_VERSION` — on ANY gameplay-affecting change** (damage, speeds, AI, economy), or stored replays re-simulate under new rules and silently play back different runs than their recorded scores claim; a version-mismatched replay shows "replay unavailable" (a sticky `watchErr` notice — the death hud repaints every tick, so one-shot `hud.innerHTML` writes get clobbered). `grantLevelToken` runs off the in-memory `runMaxwave` so replays re-grant tokens identically. The recorder caps at 50k events (`recOverflow` — marathon runs just don't ship a replay) and `lbSubmit` attaches `{replay}` when it fits 150KB. The worker stores it as its **own item** `rp#sf#<rid>` (rid = the verified run token's id; displaced entries' replays are deleted eagerly; daily replays expire with their board (4-day TTL), all-time replays get a 90-day backstop). `validateReplay` (exported for tests) is a **strict per-opcode schema, not just a size cap** — this is what keeps the endpoint useless as free hosting: event ticks must be non-decreasing and bounded by the proof-verified run length, per-tick event density is capped at human rates (12), masks are one byte, args are tiny enums, and upgrade ids must match `^[a-z0-9_]{1,24}$` (no free-form strings anywhere); invalid replays are silently dropped — never fatal to the score. Combined with the top-10 qualification gate + single-use run tokens, worst-case attacker-persistable data is hard-ceilinged at ~8 MB total (≤10 all-time + ≤10/day×4d daily replays at ≤160KB). **Recording stamp rule:** in-tick inputs are recorded at pend consumption with the current tick; **between-tick UI events (buy/continue/intro-advance/Ian) are stamped `tick + 1`** so the feeder applies them in the same between-ticks slot they happened in — stamping them with the current tick replays them one tick early and can shift tick-based cooldowns. The board entry carries `rp`. **Watching:** board rows with a stored replay show ▶; on the death screen **W opens the picker** (↑↓ choose, Enter watch, Q/W close — Escape is avoided in-game because it's the XP desktop's shutdown key). `startWatch` fetches `GET /replay?id=`, `startReplay` saves the watcher's own intro selections (`repSaved`), impersonates the recorded setup (classes, coop, `sfSeedOverride = seed`), and re-inits; the **replay feeder** at the top of `loop()` applies events stamped ≤ the current tick — masks land before the input sampler (which reads `repMask` instead of `keys` when `replayMode`), pend actions land where the pend consumer eats them, and menu/cutscene events replay through the same functions (`buyUpgrade`/`finishUpgrades`/`advanceBossIntro`/`chooseIan`) in the same between-tick slot — so the sim replays **bit-exactly**. While `replayMode` is true, **nothing of the watcher's changes**: `saveUpgrades`/`saveTokens`/maxwave writes/local-best/`lbBegin` are gated, and `unlockAchievement` is wrapped at the bridge destructure (`_unlockAch`) to no-op. `endRun` in a replay shows "so ends the legend of …"; **Q** anywhere in a replay calls `stopReplay()` (restores the watcher's selections, back to the title). onKey swallows all other input during a replay. **Cheat runs are unranked client-side**: any warp/grant cheat (`nine`, 9-spam, 8-spam) sets `cheated`, `lbBegin()` skips the board entirely, and the death screen says so. The backend stores each board in one DynamoDB item (`pk=lb#sf` all-time; `pk=lb#sf#YYYYMMDD` per day, written with a `ttl` so old days expire; `day` must be today/yesterday UTC server-side or the request is rejected) and needs no Turnstile (Origin allowlist + per-IP rate limits — including one on `/run-start` — + server-side clamping + the run proof above). A submit that wouldn't crack its top 10 is **never written** (only genuine top-10s are ever stored, so the endpoint can't be abused as free key/value storage). Backend routes (`/scores`, `/scores?day=`, `/run-start`, `/score`) live in `~/hal-worker`. **Frame driver (fixed timestep):** `loop()` no longer self-schedules — `frameStep(ts)` (the rAF callback) accumulates **wall-clock time** from the rAF timestamp into `simAcc` and advances the sim at `SIM_HZ × SF_SPEED` ticks per second **independent of the display's refresh rate** (a 120 Hz monitor renders more often but simulates no faster). The accumulated `dt` is capped at 0.25s and steps at 5 per frame, so a backgrounded tab or hitch drops ticks instead of fast-forwarding or spiraling. `loop()` = one sim tick + one render, fused — so `rnd()` consumed in render code still runs exactly once per tick (if render is ever decoupled from the sim, every `rnd()` in draw code must move into the sim first). `SF_SPEED` is 1.0 on localhost / `file:` (dev) and **1.1 when deployed** (66 ticks/s), so the live game runs ~10% faster than local. **Determinism (groundwork for replays / future lockstep MP):** the sim is a pure function of `(seed, inputs)` — all gameplay randomness goes through a seeded mulberry32 PRNG (`rnd()`, seeded per run in `init()` from `sfSeed`; a future MP layer pins a shared seed via `sfSeedOverride`) instead of `Math.random()`, and timing runs off a monotonic `tick` counter (advanced once per `loop()`, `SIM_HZ` 60) instead of the wall clock. Swing cooldown is now tick-based (`swingReadyTick = tick + ms→ticks(up.swingMs)`; `up.swingMs` stays ms in the upgrade defs, converted at the gate) — **not** `performance.now()`. The only deliberate exceptions kept on `Math.random()`: the seed draw in `init()` (the one entropy source) and `sfSfx.ora` audio pitch jitter (local/cosmetic, must not advance the shared stream). The three former TODOs are **done**: **(1) fixed-timestep driver** (see Frame driver above); **(2) per-tick input capture** — edge-triggered combat inputs (dash / attack / summon / champion-prompt / choke-mash) are queued into `pend` by `onKey` (built by `resetPend()`, cleared in `init()`) and consumed at the top of the gameplay section of `loop()`, so the sim is never mutated from inside a DOM event; with the held-key `keys` object (read once per tick), `{keys, pend}` at the tick boundary is the sim's complete input surface — the capture point for a future recorder/replayer; UI/meta input (intro rows, shop navigation, leaderboard typing, cheats, R-restart, boss-intro advance, the Ian choice) stays event-driven on purpose; **(3) settings-independent RNG** — every `api.reduceMotion` branch that used `rnd()` now **consumes the rolls unconditionally and only gates the visual effect** (rule for new code: never put `rnd()` behind a settings check — draw the numbers first, then decide whether to render), and the jojoBg/ianBg glyph recycling is rnd-free. Remaining caveats for actual cross-machine lockstep (not blockers for same-machine replays): `tick` advances during pauses/menus (shop time bleeds into tick-based cooldowns — a recorder must capture menu interactions too), `SF_SPEED` differs local (1.0) vs deployed (1.1) and `GW`/`GH` come from the desktop's size, so an MP handshake must pin speed, dimensions, and seed (`sfSeedOverride`). **Upgrades (token-based roguelite tree):** every cleared wave except the wave-5 gauntlet calls `offerUpgrade()` which grants a **token** (`tokens`) and, if anything's buyable, sets `paused` + `upMenu` so the loop overlays `drawUpgradePanel()` over the frozen field. The panel is a shop grouped by tree (DASH / ALLIES shared; BLADE / BOW / SORCERY / GRAVE are the per-class trees, shown only for classes present in the party) with an icon + name + desc per node and a token balance; `onKey` navigates (↑↓), `buyUpgrade()` spends a per-node cost (`upCost(u)` = `u.cost || 1` — most nodes cost 1, the three capstones cost 2–3 tokens; the panel shows cost as gold pips and dims unaffordable rows) on the selected node (stays open — buying re-evaluates `availableUpgrades()`, so newly-unlocked-prereq nodes appear and you can grab several in one visit), and `finishUpgrades()` (Z on Continue / Enter) banks unspent tokens and resumes into the `BREATHER` (or, post-Vader, into the Sidious reveal). **Tokens carry over**, so you can save up and unlock multiple at once. **Progression is per party profile:** the whole persisted ledger — upgrades, token balance, AND the token-paying maxwave — is keyed per profile (`upProfile()`: solo = the class name, co-op = the sorted duo, e.g. `ilaird_sf_upgrades_melee` / `ilaird_sf_tokens_caster+melee`), so each class earns and spends its own credits and never sees another's purchases. The legacy un-suffixed keys seed a profile's **first** load for upgrades + tokens (pre-split progress carries into each class once, then diverges); **maxwave deliberately does NOT seed from legacy** — every profile climbs its own token ladder from wave 1, so a fresh class isn't starved of income by the old global record. Replays are unaffected (the sim starts from the recording's `up0`/`tk0`/`mw0` header, never storage). **Cheat:** spamming `8` three times within 1.5s (`eightKeyCount`/`last8` in `onKey`) calls `grantAllUpgrades()`, which unlocks the whole tree at once (applies every `UPGRADES` node in definition order and persists via `saveUpgrades()`). ## Achievements
Easter-egg achievements (currently 44) defined in the `ACHIEVEMENTS` array in `app.js` (`{ id, name, desc, hint }`). Found ids persist in localStorage under `ilaird_eggs` (filtered against known ids on load). `unlockAchievement(id)` is idempotent — it saves, updates the 🥚 titlebar badge (`#ach-count` in `index.html`), and shows a toast. `toggleAchievements()` (global — wired to the badge's inline onclick; there is deliberately **no** `achievements` terminal command, badge-click only) lazy-loads the `achui.js` chunk on first click and opens a theme-aware overlay: unlocked entries show name + desc, locked show 🔒 + hint. Escape or clicking the backdrop closes it; while open, a capture-phase key handler shields other listeners. The mobile auto-launch calls `COMMANDS.gui(true)` so it doesn't unlock the `desktop` achievement. On load, `showEggNudge()` points a bobbing arrow at the badge (desktop only); it auto-hides after 60s, and is permanently dismissed (`ilaird_nudge` in localStorage) by its [x], clicking the badge, or opening the overlay — and never shows once any egg is found. When adding a new easter egg, add an `ACHIEVEMENTS` entry and call `unlockAchievement('<id>')` at the moment of discovery. (Stick Fighter is the exception: it keeps its own in-game trophy case — see the Trophy case section under Stick Fighter — and the site tracks only its `stick-fighter` boot egg and the `sf-platinum` full-case egg.)

The overlay UI lives in the lazy `achui.js` chunk (see Architecture) — edit it there. It has two views rendered into the same box: `renderAchList()` (the achievement list, with a `share` button in its header) and `renderShareView()` (a 1200×630 share card rendered to canvas by `buildShareCard()` using the *current* theme colors — red in HAL mode — with copy-to-clipboard (when `ClipboardItem` exists), a download link, native share (when `navigator.canShare` supports files), and a back button). Sharing is overlay-only by design — there is no `share` terminal command. The card shows a HAL eye if `meet-hal` is unlocked.
